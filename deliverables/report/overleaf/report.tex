\begin{abstract}
We measure bidirectional heuristic search on 3D voxel maps against a provable floor. For each instance we lower-bound the expansions any front-to-end algorithm must make to stay correct under a merely admissible heuristic, then report search efficiency, time, memory and robustness, direction, and heuristic strength against it. We run seven algorithms on three map families, under 6- and 26-connectivity, on a shuffled sample with a bootstrap stopping rule. Forward A*'s median sits within $6\%$ of the bound in every configuration, and BiA* and NBS hold a narrow band of $1.5$ to $1.7$ times it on the diagonal maps. BAE* falls below the floor on up to $55.6\%$ of a group's instances and at the median on one diagonal family, which is not a violation, as exploiting consistency puts it outside the class the bound covers. The sharpest results concern the gap between an algorithm and its implementation. MM times out on $77$ to $98$ percent of diagonal instances and five times the budget does not help, but the cause is a per-expansion cost that scales with the number of distinct $g$ values an incommensurable cost model produces, not the expansion bound the algorithm guarantees. NBS falls below the floor on $297$ instances, and disabling one consistency-exploiting rule in its implementation lifts the deepest of them from $0.38$ to $1.29$ times the bound with the optimal cost unchanged. As the heuristic weakens BAE* ends below A* on two of the three maps we swept, crossing over on one.
\end{abstract}

\section{Introduction}

Pathfinding is one of the most fundamental problems in artificial intelligence, navigation systems and many other fields.

The goal is to find a lowest cost path between start node and goal node.
Finding an optimal path is challenging and may require exploring many nodes.

One approach to reduce the search is bidirectional search \cite{pohl1971bidirectional}. Instead of searching only from the start, we interleave a forward search from the start with a backward search from the goal, and continue until the algorithm can guarantee that the best path found is optimal. The saving is in the volume each search covers and not in the length of the path.


\subsection{Motivation}

Even though bidirectional search seems like a promising approach, it is not always better than a unidirectional algorithm such as A*. With the right heuristic A* moves toward the goal quickly and avoids expanding unnecessary nodes, and bidirectional search has long been observed to lose to it when the heuristic is strong \cite{barker2015limitations}.

In addition bidirectional search must decide which side to continue, which node to expand, and when the best path found is guaranteed to be optimal. Those three decisions are what the algorithms in this paper differ on.

To measure an algorithm we need a baseline to measure it against. Comparing algorithms only to each other is relative, as they might all sit far from what the problem actually requires. For bidirectional search there is a stronger option. The literature gives a per-instance lower bound on the number of expansions any correct front-to-end algorithm must make, and we can compute it. Every number in this paper is a distance from that bound rather than a distance from a rival.

The domain is where this becomes interesting. The must-expand theory was developed and evaluated on unit-cost grids and on permutation puzzles. 3D voxel maps put it somewhere else. Under 26-connectivity a voxel has 26 neighbours rather than 8, the move costs are $\{1, \sqrt{2}, \sqrt{3}\}$ and share no common measure, and the maps run to roughly $1.3$ billion voxels, which makes the graph the bound is defined over too large to build explicitly. The difference is not only nominal. A published implementation of one of the algorithms we run returns suboptimal paths on this cost model, silently, for reasons we set out in the Methodology.


\subsection{Research Goal}

The goal of this project is to measure how close bidirectional search comes to that bound on 3D voxel maps, and to find where the distance changes. We run seven algorithms - A*, reverse A*, MM, NBS, BAE*, our own BiA*, and GBFS as a deliberately suboptimal reference - on the three families of \citet{nobes2023voxel}, under both movement models, with A* run from each end.

We report each algorithm along five axes: search efficiency against the floor, wall-clock time and time per expansion, peak memory together with the timeout and memory-exhaustion rates, the asymmetry between searching forward and backward on the same instance, and the response of each algorithm as we weaken the heuristic. Reverse A* is not a distinct algorithm, and we report it separately only for the direction axis.

This is a measurement question and not a ranking question. We ask how much of the room the bound identifies each algorithm actually uses, under what conditions that changes, and what it costs in time, memory and reliability. Where two algorithms separate by less than our convergence interval we report both and rank neither.

We claim four contributions. The first is the measurement itself, as the must-expand floor has not previously been computed per instance on this domain, and computing it at these contour sizes needs the threshold form rather than the graph. The second is a demonstration that the gap between a published algorithm and a widely used implementation of it is where this domain does its damage. Three of the algorithms we took from one framework depart from their published forms in ways that change what the bound says about them, and none of the three departures is announced to the user. One silently returns suboptimal paths on incommensurable move costs, one carries a rule that puts it outside the class the bound covers, and one pays a per-expansion cost that scales with how many distinct path costs the domain admits. The third follows from that, as the algorithm the theory most recommends here is the one we cannot run, and the reason is the cost of proving it may stop rather than the expansion bound it guarantees. The fourth is a caution about the benchmark itself, as its scenario files are difficulty-graded and sampling them by prefix moved our own headline figure by roughly three times.

The main sweep runs under both movement models, 26-connectivity with diagonal moves and 6-connectivity without. We treat the two as equal cases rather than one as a supplement to the other.

Our organising question is where an algorithm's theoretical efficiency (search efficiency vs. the floor) does and does not translate into practical performance (time and memory).


\section{Literature Review}

\subsection{When bidirectional search loses}
Bidirectional search is an old idea. \citet{pohl1971bidirectional} searches forward from the start and backward from the goal at once, and the argument for it is about volume rather than about path length. A single search of depth $d$ explores on the order of $b^d$ nodes, while two searches of depth $d/2$ explore on the order of $2b^{d/2}$. This is a brute-force argument. It says nothing about what happens once a heuristic guides the search.

What happens is that the saving largely disappears. Bidirectional search has long been observed to lose to A* when the heuristic is strong \cite{barker2015limitations}. A* with a consistent heuristic expands exactly the nodes with $f<C^*$ and is optimally efficient over that set \cite{hart1968astar, dechter1985generalized}, so a strong heuristic already prunes most of what a second frontier was meant to save.

The structural reason is where each heuristic points. In a front-to-end search each direction's heuristic aims at the opposite root rather than at the opposing frontier \cite{kaindl1997reconsidered}, so the two frontiers tend to pass through each other instead of meeting. Everything that follows in this section is an attempt to say how much a bidirectional search can save, and the bound we measure against is defined for that front-to-end class.

\subsection{Meeting in the middle}
\citet{holte2017mm} introduced MM, a bidirectional heuristic search algorithm that is guaranteed to meet in the middle. It is a direct answer to the frontiers passing through each other. Those algorithms do not guarantee that the two searches meet in the middle, so they can expand many unnecessary nodes. As such, a bidirectional search can lose the advantage it was meant to have.

MM is an algorithm that for forward search it does not use regular $f(n)$ alone, instead it uses priority function \[pr_F = \max(f_F(n), 2g_F(n))\] where $g_F(n)$ is the cost of the path from the start to node $n$ and $f_F(n) = g_F(n) + h_F(n)$ is regular f-function and $h_F(n)$ the estimated cost from $n$ to the goal.

The backward search uses the same priority function as the forward search but it starts from the goal node and search in the opposite direction, then MM compares the lowest priority nodes from both sides and expands node from the direction with lowest one.

The two terms do different work. $f(n)$ guides the search towards the goal, while $2g(n)$ limits how far either side may travel. Note that if $g(n) > C^*/2$ then $2g(n) > C^*$, so $pr(n) > C^*$. Any node past the halfway point therefore carries a priority above $C^*$. As MM always expands the lowest priority available, and as an unfinished search always leaves at least one node of the optimal path with priority at most $C^*$, it prefers that node over anything past the halfway point.

MM keeps $U$, the cost of the best solution found so far. Each time the two searches connect, it compares the new solution to $U$ and updates $U$ if the new one is cheaper. It stops once the lower bound reaches $U$, as no cheaper solution can exist beyond that point.

To summarise, MM guarantees that neither side expands a node with $g(n) > C^*/2$, so the two searches do meet in the middle. This is a guarantee about where they meet and not about cost. It does not follow that MM expands fewer nodes or runs faster than other algorithms. \citet{holte2017mm} report that MM0, the brute-force version that sets $h(n) = 0$ for every node, can expand fewer nodes than MM when the heuristic is weak. That is an empirical finding on their domains and not a general law. MM is one of the seven algorithms we run, and its guarantee is what our robustness axis tests.

\subsection{Must-expand pairs}
Later research changed the focus from meeting two searches in middle to which pairs of nodes expansions are necessary in algorithm with optimal solution.

And that is exactly what \citet{eckerle2017sufficient} did, switching the focus to finding necessary pairs $(u,v)$ which at least expand one node to guarantee optimal solution. where $u$ is a forward-frontier node and $v$ a backward-frontier node.

They did this by defining lower bound on the cost of any solution path passing through the pair by function \[lb(u,v) = \max\{f_F(u), f_B(v), g_F(u)+g_B(v)\},\] using this function they defined the followed rule $(u,v)$ is a must-expand pair if $lb(u,v) < C^*$. This means at least one of two nodes must be expanded to guarantee optimal solution.

This is because when $lb(u,v) < C^*$ the algorithm cannot discard the possibility of a path through $u$ and $v$ with cost lower than $C^*$, so it must expand one at least.

This work provided a way to identify the expansions that are necessary in bidirectional search. It does not say which of the two nodes in a pair should be expanded. As such, an algorithm is free to pick the more expensive of the two. This result reframes the question the field asks, from how to design a better algorithm to what any correct algorithm must do. That is what makes measurement against a fixed floor possible, and this pairwise condition is what our own floor is computed from. Note also that the result has a scope, which we return to below.

\subsection{The must-expand graph and its minimum cover}
\citet{chen2017nbs} represented the must-expand pair at different way, it represented as must-expand graph $G_{MX}$, where each edge represents pair. Therefore, the minimum number of necessary node expansion is the minimum vertex cover of the graph then \citet{shaham2017minimal} studied the structure of the new graph and its minimum cover.

Building the full $G_{MX}$ is expensive, and \citet{shaham2017minimal} show that it is not necessary. Nodes that share a $g$ value behave identically in the graph, as the edge condition depends on $g$ alone. As such, they can be collapsed into groups. Let $G_F(i)$ be the set of forward nodes with $g_F = i$, and likewise for the backward side. There is an edge between two groups iff $g_F + g_B < C^*$.

In this collapsed graph the MVC has a simple structure, and \citet{shaham2017minimal} show that it is fixed by a single meeting point between the two searches. On that basis they introduce $fMM(p)$, where $p \in [0,1]$ sets how far each side may travel. The forward search may not pass $p \cdot C^*$, and the backward search may not pass $(1-p) \cdot C^*$.

The algorithm uses the priority functions 
\begin{align*} 
    pr_F &= \max(f_F(n), g_F(n)/p)\\ 
    pr_B &= \max(f_B(n), g_B(n)/(1-p))
\end{align*}

Each instance therefore has its own optimal $p^*$, and finding it requires knowing $C^*$ and the distribution of nodes in $G_{MX}$ before the instance is solved. As such, the algorithm is more theoretical than practical.

The experiments showed that the optimal $p$ changes between problems.

\citet{chen2017nbs} also introduce NBS, which uses the cover directly. At each step NBS takes the pair with the lowest $lb$ and expands both of its endpoints, so it never spends more than two expansions where a minimum cover would spend one. Their Theorem 3 bounds its expansions at twice the minimum vertex cover, and their Corollary 4 states the same against any admissible front-to-end algorithm. Note that the bound is on the expansions made in covering the must-expand pairs, meaning the pairs with $lb(u,v) < C^*$ strictly, and not on total expansions. Expansions at $f = C^*$ fall outside that accounting, and \citet{chen2017nbs} note that NBS may make many of them where another algorithm does not.

Two limits on the framework follow, and together they set the scale for anything measured against this floor. The first is that no front-to-end algorithm of the class the bound covers has a worst case better than twice it, as \citet{shaham2017minimal} show that for every DXBB algorithm there is a worst-case graph on which it expands twice as many nodes as the minimum vertex cover contains. The second is that the bound is attained only by $fMM$ given the correct $p$, which \citet{shaham2017minimal} show to be the optimal front-to-end bidirectional search. Note that three different statements about the factor of two are now in play, and they run in different directions. NBS's guarantee, above, bounds a single algorithm from above. The class-wide limit bounds from below what any algorithm in the class can achieve, so the factor of two is not an artefact of NBS's design but the best worst case the class allows. Attainability is about neither, as it says that reaching the bound itself rather than twice it needs a parameter that cannot be known before the instance is solved. The minimum vertex cover of $G_{MX}$ is the quantity we compute for every instance in this paper, and every score we report is an algorithm's expansions divided by it.

\subsection{The class the bound covers}
The bound is narrower than it first appears, and the narrowing is what explains two of our own results. \citet{eckerle2017sufficient} work with two sets of instances. An instance is bi-admissible when both heuristics are admissible, and bi-consistent when both are also consistent. Their theorem covers any admissible DXBB algorithm, where DXBB stands for Deterministic, Expansion-based, Black Box and is the class their conditions define, with front-to-end a separate restriction on which nodes an algorithm may compare, and where admissible means that the algorithm returns an optimal solution on every bi-admissible instance and not only on the bi-consistent ones.

That last quantifier carries the whole result. The proof builds an adversary instance which is bi-admissible but need not be bi-consistent, so an algorithm whose correctness rests on the heuristic being consistent is never required to handle that instance and is not bound by the result. \citet{eckerle2017sufficient} name BS* \cite{kwa1989bs} as exactly this case and leave it as open work in their conclusions, and BS* is the algorithm that introduced the nipping and pruning rules we meet again in the results. \citet{sadhukhan2013bae} give BAE*, whose error term carries the same requirement, and \citet{alcazar2020unifying} set out the machinery it rests on. \citet{alcazar2021consistent} carries that extension out, and \citet{siag2023frontToEnd} enumerate the bounds available once consistency is assumed. Note that this is how an algorithm can score below the floor without anything having gone wrong, which we return to in the results.

\subsection{Meeting at a threshold}
Building on the previous limitations and results \citet{shaham2018consistent} introduced Meet at the Threshold (MT). MT is close to fMM, with one difference - it uses a fixed threshold $t$ rather than a fraction $p$ of $C^*$. The forward search does not expand a node with $g_F > t$, and the backward search does not expand a node with $g_B > C^* - t$. Setting $t = pC^*$ makes MT expand the same set of nodes as $fMM(p)$, but $t$ stays constant, which makes it simpler to analyse.

The authors extended the previous theory to two case each case give additional information.

In the first case the algorithm knows that every edge costs at least $\varepsilon$. That changes the must-expand condition to $g_F(u) + g_B(v) + \varepsilon < C^*$. As a result, some edges are removed from the new $G_{MX}$, which makes the MVC smaller.

Therefore they extend MT to $MT_{\varepsilon}$, where the forward and backward thresholds satisfy $t_F + t_B + \varepsilon = C^*$. These thresholds decide which nodes the algorithm expands. With the optimal threshold, it expands the minimum number of nodes.

In the second case the algorithm knows that both heuristics are consistent. That allows a lower bound between two nodes to be built from the differences between their heuristic values, \[h_C(u,v)=\max\left(|h_F(u)-h_F(v)|,\ |h_B(u)-h_B(v)|\right),\] and the must-expand condition becomes $g_F(u) + g_B(v) + h_C(u,v) < C^*$. As in the previous case, this can remove edges from $G_{MX}$.

Here a single threshold no longer describes the MVC. The authors instead group nodes by their $h_F$ and $h_B$ values, so that every node in a group shares the same pair, and give each group its own threshold. On that basis they introduce MTCON, which replaces the single threshold with a function $b(h_F,h_B)$. A forward node is expanded only if $g_F < b(h_F,h_B)$, and a backward node only if $g_B < C^* - b(h_F,h_B)$. Given the correct $b$, MTCON expands the minimum number of necessary nodes. This function is unknown in advance, as $p^*$ is for fMM.

Overall the paper shows that knowing information like lower bound for edges value and heuristics can reduce the number of necessary node expansions. Two things from it carry into this paper. The nested structure of the collapsed graph is what lets the cover be computed in threshold form, and without it $G_{MX}$ would have to be built explicitly, which our contour sizes rule out. And both parameters this line of work rests on, $p^*$ for fMM and $b$ for MTCON, require knowing the answer before they can be used to find it.

\subsection{Individual bounds and heuristic inaccuracy}
\citet{alcazar2020unifying} take a different approach, building stronger lower bounds from sources such as heuristic inaccuracy. They show that a bound can be defined per node. Write $LB(n)$ for the lower bound on the cost of any solution through $n$, and $C_{lb}$ for the global lower bound on the optimal solution cost. Whenever $LB(n) > C_{lb}$, node $n$ is not expanded yet and its expansion is deferred.

To make these individual bounds stronger they use heuristic inaccuracies, which measure the difference between the $g$ value of node $n$ and the heuristic estimate from the opposite direction, $d_x(n) = g_x(n) - h_{\bar{x}}(n)$. That difference raises the lower bound on $n$, which brings it closer to the true solution cost.

They use this difference to build the KK bound, which combines the minimum $f$ value from one direction with the opposite direction's minimum $d$ value, and is stronger than the $f$ value alone. They also define the bidirectional estimate $b_x(n) = f_x(n) + d_x(n)$. This is the value BAE* expands on. BAE* itself is due to \citet{sadhukhan2013bae}. Its error term is meaningful only when the heuristic is consistent, which places it outside the class of the previous subsection, and \citet{alcazar2021consistent} carries the must-expand theory into that consistent case. BAE* is one of the seven algorithms we run, and this machinery is what explains both its scores below the floor and its behaviour as the heuristic weakens. They also introduce DBS and DBBS - DBS uses the g-bound and the kk-bound, while DBBS uses the b-bound. Their experiments show that these bounds reduce expansions overall, with BAE* performing best under them and DBS and DBBS ahead on some instances.

\subsection{Connecting must-expand pairs and search bounds}
Two lines of work had been running in parallel - the must-expand pairs theory on one side, and algorithms driven by search bounds on the other. \citet{siag2023frontToEnd} connect them, by deriving the bounds from the must-expand conditions themselves.

The derivation rests on one observation, applied to a sharper pair bound than the one above. Where consistency is available the pair bound can be written \begin{align*}
lb_C(u,v)=\ &g_F(u)+g_B(v)\ +\\
&\max\left(h_F(u)-h_F(v),\ h_B(v)-h_B(u),\ \varepsilon\right),
\end{align*} which is the form \citet{siag2023frontToEnd} work from. That bound is again a maximum over three expressions, and a maximum is at least the average of any subset of them, so the average of each combination is itself a lower bound. Taking the single terms recovers the g-bound and the two KK bounds, which \citet{alcazar2020unifying} had already given, and taking the pairs and the triple yields the b-bound together with further bounds that had not been stated before.

They then place those bounds inside a general framework for bidirectional search, built around three decisions. The first is when to stop, where the bound is what certifies the solution in hand as optimal. The second is which node to expand, where the framework prefers the node that raises the bound fastest. The third is which direction to expand, and they compare three policies - alternating, a cardinality criterion, and Fastest Bound Increase, of which only the last consults the bound.

From the framework they build a family of algorithms they call Targeted Bound. Each $TB_i$ targets one bound $B_i$, choosing the nodes that raise it, while using all of the bounds for termination. $TB_4$ targets the b-bound, which makes it close to BAE*. They also examine DBBS, which computes its bounds dynamically rather than targeting a fixed one. That can cut expansions, but the computation is not cheap and it costs running time.

Their results bear on what we measure. The b-bound is among the strongest, and when the heuristic is weak $B_7$ can overtake it. DBBS sometimes expands fewer nodes and still finishes slower. And on some domains BAE* comes close to the minimum number of expansions outright, which suggests there is little room left to beat it by choosing a different bound. Note that on this domain we find BAE* going further still, below the floor itself on a large share of instances, which the results take up.

\subsection{Benchmarks for 3D pathfinding}
Comparing these algorithms needs domains to compare them on, and it needs more than one of them. \citet{nobes2023voxel} supply three families of 3D voxel maps, chosen so that the geometry differs in ways search is sensitive to - confinement against open volume, and regular structure against irregular. That separation is what makes the set useful here, as the must-expand bound is a statement about the shape of the two $f<C^*$ contours, and a contour grows differently in a winding pore than in an open hall. The Methodology describes what each family actually is.

Supplying the maps is only half of it, as the instances matter as much as the geometry. Choosing start and goal at random is not enough, as most random pairs turn out easy. \citet{nobes2023voxel} measure difficulty by the number of nodes A* expands under their voxel heuristic, which is the 26-connected distance, so that a harder instance is one that costs more to solve. They also run A* in the opposite direction on every instance, to check that an instance is not hard only because of the direction it is stated in, and they keep the smaller of the two counts. Note that they then write each instance out in whichever direction produced that smaller count. As such the published orientation is not neutral - forward search is the easier direction by construction, which is what our directional axis has to measure around. From the graded set they publish 2000 instances per map, spread across difficulty levels.

\subsection{Where this leaves us}
This project runs the algorithms above on those benchmarks and measures them against the must-expand floor rather than against each other. We run both movement models. The 26-connected case, where a voxel has 26 neighbours and edge costs of $1$, $\sqrt{2}$ and $\sqrt{3}$, is the harder setting for this theory, as both the branching factor and the cost structure sit further from the unit-cost grids the theory was developed on. \citet{shaham2017minimal} report a ratio of this kind already, for four algorithms on eight domain and heuristic pairs of 2D grids and puzzles, aggregated over instances and counting only the expansions below $C^*$. What the work above does not give is the per-instance distribution of that ratio, over total expansions, for seven algorithms, on a domain whose move costs share no common measure. Nor does it say where the crossover against A* falls as the heuristic weakens. Both are empirical questions, and this paper asks them.

\section{Methodology}
\subsection{Domain and Algorithms}
\subsubsection{Domain}
For this project, we used the Warthog 3D voxel maps as our main benchmark. The three families we use are introduced by \citet{nobes2023voxel}, in the file format established by \citet{brewer2018voxel}. This benchmark holds two types of files:
\begin{itemize}
    \item \texttt{.3dmap} - The map file. Holds the grid dimensions and the set of blocked voxels.
    \item \texttt{.3dscen} - The scenario file. Holds the start/end pair coordinates, as well as a reference optimal cost for each.
\end{itemize}
The three families are:
\begin{itemize}
    \item Industrial plants - process-plant environments built from anonymised layout data, with component geometry replaced by bounding boxes at 10cm resolution. These hold the greatest proportion of traversable space of the three families, mixing large voids with narrow ones.
    \item Sandstone - micro-CT scans of porous sandstone rock, with winding narrow pores and irregular, non-symmetric natural structure.
    \item Descent - 3D maze-like levels from the game Descent, dominated by winding corridors and enclosed rooms.
\end{itemize}
We used 5 plant maps, 11 sandstone maps and 29 of the 30 descent levels - one descent level is omitted, as its instances did not complete within our cluster allocation. Their sizes range from plant01 at $195\times128\times100$ voxels up to the largest descent levels at roughly 1.3 billion voxels. Each map holds a scenario file of 2000 instances, and we run a representative sample of those as described in the sampling and stopping rule subsections below.

\subsubsection{The two movement models}
In this paper we explore the search algorithms within two distinct movement models:
\begin{itemize}
    \item 6-connectivity (axis aligned) - In this movement model, the only directions the search algorithms are allowed to move in are axis-aligned ($\pm1$ in $x$, $\pm1$ in $y$, $\pm1$ in $z$). In this context, every movement direction holds the same cost of 1 unit.
    \item 26-connectivity - In this movement model, the search algorithms are allowed to move to any of the 26 neighbors of a certain voxel (including diagonals). In this instance, the cost of each movement aligns with its direction: face (2 of the same x,y,z, the remaining one is $\pm1$) - 1 unit, edge (1 of the same x,y,z, the other two are $\pm1$) - $\sqrt{2}$ units, corner (all of x,y,z are $\pm1$) - $\sqrt{3}$ units. In this mode there is the additional constraint of no corner-cutting in diagonal moves, which follows the benchmark's own move model \cite{nobes2023voxel}. A move from a voxel $p$ by an offset $d$ is legal only if every voxel in the axis aligned box spanned by $p$ and $p+d$ is free. To check this, we take $d$, zero out any non-empty subset of its non-zero components, and require the resulting voxel to be free in every case. For an edge move (2 changed coordinates) this checks 2 face neighbours as well as the target. For a corner move (3 changed coordinates) it checks 3 face neighbours and 3 edge neighbours as well as the target.
\end{itemize}
We run both as each changes the branching factor and the heuristic, and with them the search dynamics.

\subsubsection{The heuristic}
We used coordinate differences in each movement model respectively: 6-connectivity - Manhattan distance, 26-connectivity - the 3D octile or voxel heuristic, which \citet{nobes2023voxel} define as the obstacle-free 26-connected distance and which is the 3D analogue of the 2D octile heuristic \cite{sturtevant2012benchmarks}. We write $\delta_1 \le \delta_2 \le \delta_3$ for the sorted absolute coordinate differences between $n$ and the target, and define:
\begin{itemize}
    \item Manhattan: $h(n) = \delta_1 + \delta_2 + \delta_3$.
    \item 3D octile: $h(n) = \sqrt{3}\,\delta_1 + \sqrt{2}\,(\delta_2-\delta_1) + (\delta_3-\delta_2)$.
\end{itemize}
We note that both of these heuristics are proven admissible and consistent. Each one is the exact shortest path cost from $n$ to the target in the obstacle free grid. Admissibility follows as removing the obstacles only relaxes the problem, so the obstacle free cost never exceeds the true cost \cite{pearl1984heuristics}. Consistency follows as each heuristic is a metric on the grid and so obeys the triangle inequality, and as each edge cost equals the free space distance of its own move.

We rely on consistency again later - it is what lets us compute the must-expand bound in threshold form, and it is why a node's $g$ value is optimal when it is first expanded. Note that consistency also does more than that, and we return to it when we explain which algorithms the bound covers.

\subsubsection{The algorithms}
In this paper we explore seven algorithms and run them against the same benchmark:
\begin{itemize}
    \item A* - The classic A* algorithm as outlined in \citealt{hart1968astar}.
    \item Reverse A* - The same classic A* algorithm \cite{hart1968astar}, but we start from the goal and progress towards the start. It is not a distinct algorithm, but we report it separately for the direction axis.
    \item MM - Meet in the Middle, as outlined in \citealt{holte2017mm}. HOG2 implements the MMe variant, which expands on the priority $max(f, 2g+\varepsilon)$ with $\varepsilon$ a lower bound on the edge costs, set to $1$ here. The $2g$ term is what keeps either frontier from passing the midpoint, as the literature review sets out, and the $\varepsilon$ term tightens the halfway point to $(C^*-\varepsilon)/2$. That difference is small and it matters for the scores we report, so we return to it in the results.
    \item NBS - Near-optimal Bidirectional Search, as outlined in \citealt{chen2017nbs}. It chooses the next pair to expand so that its expansions stay within a factor of 2 of the necessary number.
    \item BAE* - Bidirectional A* with Error, as outlined in \citealt{sadhukhan2013bae}. It expands on the priority $b = f + d$, with $d$ being the accumulated error term, which \citet{kaindl1997reconsidered} first used to strengthen a consistent heuristic by measuring its inaccuracy in the opposite direction. As implemented in HOG2 \cite{sturtevant2016hog2}, its lower bound is rounded up to the next multiple of the gcd of the edge costs, a device defined in the bound framework of \citet{alcazar2020unifying}, and that gcd defaults to 1. This rounding is only valid when every solution cost is a multiple of the gcd. Our costs $\{1, \sqrt{2}, \sqrt{3}\}$ are incommensurable, so no positive gcd exists and the tightening cannot be applied at all. At the default it inflated the bound to the next integer, and the termination test fired before optimality was proven, which returned suboptimal paths. Note that it did so silently, with no error and no warning. We caught it only through the correctness checks described below - the reference cost in the \texttt{.3dscen} file, and the disagreement between BAE* and the other optimal algorithms, which also told us that BAE* was the one at fault. The parameter is exposed, so the fix is available, and we set the gcd to $10^{-6}$. The rounding is then negligible. BAE* then matches the optimal cost on every instance. Note that the defect is specific to BAE* among the algorithms we take from HOG2, as the bound rounding is in its implementation alone. The looser bound costs it extra expansions, so our BAE* expansion counts are not directly comparable to published results on integer cost domains.
    \item BiA* - Bidirectional A*, as outlined in \citealt{pohl1971bidirectional}. As this algorithm was not implemented in HOG2 \cite{sturtevant2016hog2}, we implemented it ourselves. It expands on the priority $f = g+h$. We write $U$ for the cost of the best solution found so far, and $fmin_F$, $fmin_B$ for the smallest $f$ value on each open list, with $f$ as defined in Notation below. It terminates when $U \le max(fmin_F, fmin_B)$. It strictly alternates between the two directions, and breaks $f$ ties by the larger $g$. A node that is already closed on the opposite side is skipped and not expanded.
    \item GBFS - Greedy Best First Search \cite{pearl1984heuristics}. We use HOG2's bidirectional variant, which grows a greedy search from each end and joins them, so its reported cost is the sum of the two halves. It is not guaranteed to return an optimal solution. We include it as a fast, suboptimal reference point, and not as a candidate for the must-expand bound.
\end{itemize}
A* and reverse A* are unidirectional. MM, NBS, BAE*, BiA* and GBFS all run two searches. Of those five, MM, NBS, BAE* and BiA* are front-to-end and optimal - each direction's heuristic aims at the opposite root rather than at the other frontier \cite{kaindl1997reconsidered}. The must-expand floor, which we define in the next subsection, is defined for that class.

\subsection{The Must-Expand Floor}
We use the must-expand floor \cite{eckerle2017sufficient, shaham2017minimal}. \citet{eckerle2017sufficient} give the pairwise condition this rests on, and \citet{chen2017nbs} turn it into a lower bound on expansions - the minimum vertex cover of the graph of pairs that must be separated. The closer an algorithm comes to that bound, the better.

\subsubsection{Notation \& $C^*$}
In the bidirectional domain we conduct two searches, forwards ($F$) from a starting node $s$ and backwards ($B$) from a goal node $t$. We define:
\begin{itemize}
    \item $g_F(n) = d(s,n)$ = The optimal cost of a path $s \to n$.
    \item $h_F(n)$ = Heuristic for $n \to t$.
    \item $f_F(n)$ = $g_F(n)+h_F(n)$
    \item $g_B(n) = d(n,t)$ = The optimal cost of a path $n \to t$.
    \item $h_B(n)$ = Heuristic for $n \to s$.
    \item $f_B(n)$ = $g_B(n)+h_B(n)$
    \item $C^*$ = The optimal solution cost. We compute it from a full A* solve, summing the edge costs along the recovered path. We deliberately choose not to use the value stored in the \texttt{.3dscen} file - it is rounded to roughly 6 significant figures, and under the "<" conditions below that rounding could misclassify a node sitting exactly on the boundary.
\end{itemize}
In 26-connectivity every path cost is a sum of $1$, $\sqrt{2}$ and $\sqrt{3}$, so $C^*$ has no exact floating point representation. We compute it with the same arithmetic and the same summation as the $g$ values it is compared against, so the discrepancy stays at accumulated double precision error. The stored value's error is relative, at 6 significant figures, so on our larger instances it passes $10^{-2}$ in absolute terms - four orders of magnitude coarser than what our own comparisons use. We compare against $C^*$ with a small absolute tolerance, applied conservatively so that anything within it of the boundary is dropped rather than added, which keeps the floor a valid lower bound. In 6-connectivity all costs are integers and the comparisons are exact. Appendix~A gives the tolerances and the error budget behind them.

\subsubsection{Must-expand nodes \& the graph}
We restate the pair bound from the literature review, as the derivation below rests on it: $lb(u,v)=max(f_F(u), f_B(v), g_F(u) + g_B(v))$ \cite{eckerle2017sufficient}. A pair is a must-expand edge if and only if $lb(u,v)$ < $C^*$. As $lb$ uses a maximum, for $lb$ to be less than $C^*$, all three have to be true:
\begin{itemize}
    \item $f_F(u)$ < $C^*$ - the forward search cannot yet rule out an optimal path through $u$. Equivalently, $u$ lies inside the forward $f<C^*$ contour, meaning the set of nodes whose forward $f$ value is below $C^*$.
    \item $f_B(v)$ < $C^*$ - the backward search cannot yet rule out an optimal path through $v$. Equivalently, $v$ lies inside the backward $f<C^*$ contour.
    \item $g_F(u) + g_B(v)$ < $C^*$ - no path that visits $u$ and then $v$ can cost less than $g_F(u)+g_B(v)$, and that bound is still below $C^*$, so we cannot yet rule such a path out.
\end{itemize}
If $lb(u,v)\ge C^*$, then no path through $u$ and $v$ costs less than $C^*$. As such, that pair cannot hide a cheaper solution, and an algorithm may return an optimal path without expanding $u$ in the forward search or $v$ in the backward search. Conversely, if $lb(u,v)$ < $C^*$, then the algorithm cannot yet reasonably prove that the optimal path does not go through these two nodes, and as such, at least one of $u$ and $v$ must be expanded \cite{eckerle2017sufficient}.

Additionally, we also define $G_{MX}$ to be a bipartite must-expand graph, following \citet{chen2017nbs} and \citet{shaham2017minimal}. Its two sides are disjoint copies of the voxel set - a forward copy $L=\{u_F : f_F(u) < C^*\}$ and a backward copy $R=\{v_B : f_B(v) < C^*\}$. A voxel that is both a forward and a backward candidate appears once on each side, as expanding it in the forward search and expanding it in the backward search are two different actions. An edge $(u_F,v_B)$ exists in $G_{MX}$ iff $(u,v)$ is a must-expand pair. The two copies of one voxel are never adjacent, as $d(s,n)+d(n,t)\ge d(s,t)=C^*$ for every $n$ by the triangle inequality. As a correct algorithm must expand $\ge1$ endpoint of each edge, the set of nodes it expands is a vertex cover of $G_{MX}$.

As \citet{chen2017nbs} show, any algorithm of the class this bound covers must expand at least a vertex cover of $G_{MX}$. As such, a minimum vertex cover (MVC) of $G_{MX}$ is a lower bound on the number of expansions such an algorithm must perform to ensure optimality.

\subsubsection{Computation}
$G_{MX}$ is bipartite, so its minimum vertex cover is computable in polynomial time by maximum matching. Size is what stops us, as the graph has up to $|L|\times|R|$ edges over contours of $10^5$ to $10^8$ voxels and cannot be built explicitly. To work around this, we notice that with a consistent heuristic the edges of $G_{MX}$ have a nested structure, and the optimal cover takes a threshold form \cite{shaham2018consistent}. We count only over the vertices of $G_{MX}$. We define the two counts as \begin{align*} N_F(\tau) &= \#\{u_F \in L : g_F(u) < \tau\}\\ N_B(\tau) &= \#\{v_B \in R : g_B(v) < \tau\} \end{align*} and the optimal cover is then \[|VC| = \min_\tau \left( N_F(\tau) + N_B(C^*-\tau) \right)\] Membership in $L$ and $R$ already carries the $f<C^*$ conditions, so both counts range over $G_{MX}$ and not over the whole voxel set.

Let $S_\tau = \{u_F \in L : g_F(u) < \tau\} \cup \{v_B \in R : g_B(v) < C^*-\tau\}$. The union is disjoint, so $|S_\tau| = N_F(\tau) + N_B(C^*-\tau)$. Every $S_\tau$ is a valid cover, and for a graph whose neighbourhoods are ordered by inclusion some threshold cover attains the minimum \cite{shaham2017minimal}, so $\min_\tau|S_\tau|$ is the MVC itself and not merely an upper bound on it. Appendix~C gives both steps, the source we take tightness from, and the two checks we ran against the scan.
To obtain the two $g$-value multisets, we expand each direction's full $f<C^*$ contour, keeping one entry per node so that duplicate $g$ values are counted separately. Note that a consistent heuristic makes a node's $g$ value optimal when it is first expanded, so these expansions recover exactly $d(s,\cdot)$ and $d(\cdot,t)$. We compute $C^*$ first, and then the two contours. $|S_\tau|$ is constant between consecutive values of $\{0\} \cup \{g_F(u)\} \cup \{C^*-g_B(v)\}$, so we evaluate it once on each interval and take the minimum.

We compute the floor once per (instance, mode, $w$), in a separate binary that runs as its own step before the measured runs. It costs a full A* solve for $C^*$ plus a forward and a backward contour expansion. That is more work than any algorithm we measure. As it is a separate process, the wall-clock and peak memory we report cover the search algorithm alone. Every instance in our runs received a computed floor, so no instance is left out of axis A for want of one.

\subsubsection{Reporting}
When reporting an algorithm's score, we report it as $\text{\# of expansions} \div \text{MVC}$, which we write as exp/floor throughout. We count expansions per direction, which matches the units of the cover. With a consistent heuristic no node is re-expanded, so the numerator and the denominator are in the same units. A score of 1 means the algorithm expanded exactly as many nodes as the bound requires. Scores below 1 are possible for some of our algorithms, and the next paragraphs say which and why.

We report exp/floor for the six algorithms that guarantee optimality, and not for GBFS. For GBFS we report the raw expansions alongside its solution cost relative to $C^*$.

The bound covers only admissible DXBB algorithms, meaning front-to-end algorithms that must stay correct under a merely admissible heuristic. An algorithm whose correctness relies on the heuristic being consistent is not in that class and is not bound by the result. Our own BiA* is such an algorithm - it discards a node already closed on the opposite frontier. That is sound only because consistency makes that node's $g$ value final. BAE* is another, as its error term is meaningful only under consistency. \citet{eckerle2017sufficient} name this gap as open work in their conclusions, \citet{alcazar2021consistent} extend the must-expand theory to the consistent case, and \citet{siag2023frontToEnd} enumerate the bounds available once consistency is assumed.

As such we read exp/floor as distance from a bound that covers algorithms correct under admissible heuristics, and we expect the consistency-exploiting ones to fall below it. Unidirectional A* is the exception that anchors the scale. It corresponds to the degenerate cover in which the backward search contributes nothing, so with a consistent heuristic it expands every node with $f<C^*$ and no node twice \cite{dechter1985generalized}. That set is exactly the all-forward cover. Its score therefore cannot fall below 1.

Swapping $s$ and $t$ maps the forward side of $G_{MX}$ onto the backward side, so the MVC is the same in both directions. As such, forward and backward scores are comparable against the same denominator.

Note that exp/floor is undefined when $\text{MVC}=0$. This happens exactly when $h(s)=C^*$ - no node then has $f_F<C^*$, so $G_{MX}$ has no edges. We call an instance non-trivial when $\text{MVC}\ge1$, and we leave the trivial instances out of axis A while keeping them for the other axes. The instances this removes are the ones where the heuristic is already exact. They are not simply the short ones. As such, axis A describes the heuristic-inexact instances. The excluded fraction differs sharply between the two movement models, as Manhattan is exact far more often in 6-connectivity. We report it per group with the results.

\subsection{Implementation and Metrics}
\subsubsection{Implementation}
Our search core is HOG2 \cite{sturtevant2016hog2}, which implements most of the algorithms we evaluated. On top of it we built the voxel environment, implementing both connectivity modes, no-corner-cutting, the weight knob, the floor computation, and BiA*. All of our code is C++17, compiled with g++ at -O2. We ran everything on the BGU HPC cluster, with one CPU core per run.

\subsubsection{Protocol}
We ran all algorithms against instances of each of the three map families described above, under both movement models. An instance is defined as a (map, start, goal) triple, taken from that map's scenario file. We selected which instances to run as explained in the next section. To measure directional asymmetry we ran A* from each end of every instance, which is what reverse A* is. The other five algorithms search from both ends within a single run, GBFS included, as HOG2's variant of it is bidirectional. As such the direction axis covers A* alone, which is the only unidirectional algorithm we run and so the only one for which forward and reverse are distinct.

We cap each run at 60 s of wall-clock time, and at an address space limit of 4000 MB in 6-connectivity and 7000 MB in 26-connectivity. A run that exceeds the time cap is recorded as a timeout, and one that exhausts the address space cap as a failure. Either way the instance is recorded as unsolved rather than dropped. That holds within a completed cluster task. Two descent levels under 26-connectivity lost their tail runs to the node's wall-clock limit instead, and we report that gap with the results. Note that we do not cap the runs to make them terminate - the graph is finite, so every search terminates on its own. We cap them to stay inside our memory and compute budget, as the largest searches otherwise exhaust the available memory and die. We chose the caps to fit our compute budget and did not derive them in advance, and we report the resulting timeout rates per algorithm rather than arguing that the caps are harmless. The memory caps are set from observed peak virtual usage per mode, with headroom above the largest peak we saw. Note that the cap is on address space, while the figure we report in the memory axis is peak resident memory. A search can exhaust its address space while its resident peak is still well below the cap, so a memory failure does not imply a peak close to the cap.

\subsubsection{Sampling}
Each map holds 2000 instances. Running all of them is expensive, and offers little advantage over a representative sample.

Instances in the scenario files are graded by difficulty. The grading is not strictly monotonic, but easier cases are generally placed before their harder counterparts - the first 250 sandstone instances have a mean optimal cost of about 305, against about 536 over the full 2000. As such, any prefix of the file is systematically easy. To correct this, we shuffle each map's instance list with a fixed seed and interleave the maps, so that every prefix of the resulting order is itself a representative sample of the family. This prefix property is what our stopping rule needs.

\subsubsection{The stopping rule}
We then run instances in that order in rounds, and after each round we check whether the estimate has settled. For each (family, mode, algorithm) we track the median exp/floor and its bootstrap $95\%$ CI (Confidence Interval), computed as a percentile bootstrap over 2000 resamples of the per-instance values with a fixed seed. A group counts as converged when the CI half-width is within $\pm3\%$ of the median, and at least 50 instances contribute to it. We need that minimum as exp/floor is concentrated on a few exact values, so a small sample can give a zero-width interval that would otherwise read as convergence. The first round runs 500 instances per map.

We make the extension decision per (family, mode) rather than per algorithm. If any algorithm in a group has not converged, we extend the whole group and re-run every algorithm over the enlarged range, up to all 2000 instances. As such, all algorithms in a group share one common instance prefix. Their medians are comparable for that reason. Note that the ratio is undefined at $\text{MVC}=0$, so only the non-trivial instances contribute to a CI - the effective sample size is smaller than the number of instances we ran, and substantially so in 6-connectivity. We read the $\pm3\%$ interval as a convergence diagnostic rather than as an inferential interval, and we do not rank two algorithms whose medians separate by less than it.

\subsubsection{The rounds we ran}
The first round ran 500 instances per map in every group. Sandstone and descent under 6-connectivity reached the target there. The rule called for another round on the remaining four groups, and we ran that round on plants, which took both plant groups to 1500 instances per map. Our final sample is therefore 1500 instances per plant map and 500 per sandstone and descent map. That is 7500 instances per mode on plants, 5500 on sandstone and 14500 on descent.

We did not extend the two 26-connected groups the rule flagged, and their round-one numbers show why. At 500 instances per map every algorithm in them except MM was already inside the target. MM was not, and MM could not be. Its interval is set by how many instances it solves, and it times out on $94\%$ to $98\%$ of those two groups, so adding instances there enlarges the pool without enlarging MM's sample. Sandstone and descent are also our largest families, at 11 and 29 maps against 5 for plants, so the round we did not run is also the expensive one.

\subsubsection{Correctness}
We verify optimality rather than asserting it, in three independent ways: an auditor that re-implements the move rule from scratch and checks every successor and every returned path for legality, a comparison of every returned cost in 26-connectivity against the reference optimum in the \texttt{.3dscen} file, and a check that all optimal algorithms agree on $C^*$ in both modes. All three passed on the runs they cover. The second is an oracle external to our implementation, which agreement among our own algorithms cannot give us, and it is what localised the BAE* defect above. Appendix~D states each check, its tolerance and its coverage.

\subsubsection{Metrics}
We report each algorithm along five complementary axes:
\begin{enumerate}
    \item[(A)] Search efficiency - node expansions relative to the must-expand floor. This is our primary axis, as it measures how close an algorithm comes to the provable minimum amount of work.
    \item[(B)] Time - wall-clock runtime and time per expansion. The latter separates search work (how many nodes) from per-node overhead. We read wall-clock as a practical measure, since it also reflects our implementation. BiA* is our own code and the rest come from HOG2, so any wall-clock comparison involving BiA* mixes implementation quality with algorithm.
    \item[(C)] Memory and robustness - the peak resident memory per run, and the rates of timeout and of memory exhaustion, both over all attempted instances. We keep the two rates apart, as running out of time and running out of memory say different things about an algorithm. Together with peak memory they capture whether an algorithm is practical to run, not just efficient in node count.
    \item[(D)] Direction - the asymmetry between searching forward (start to goal) and backward (goal to start) on the same instance.
    \item[(E)] Heuristic strength - how each algorithm's expansions change as the heuristic is weakened, measured by the heuristic strength experiment described below.
\end{enumerate}
Throughout this experiment, we focused on the median as opposed to the mean. We did this as the distribution of expansions is heavy-tailed, and several especially hard instances can skew the mean. The timeout and memory-exhaustion rates are kept as guardrails, bounding which instances each median covers. Note that the unsolved instances are the hardest ones, so a median over the solved instances is optimistic, and most optimistic for the algorithms with the lowest coverage. As such, we read the medians together with coverage. Note that the per-group medians are each taken over that algorithm's own solved instances, which is why we report coverage beside them, and that where we compare algorithms head to head we use a set every one of them solved. Note that we form every ratio per instance and then take the median of those ratios, for exp/floor and for the BAE* against A* comparisons alike.

\subsection{Heuristic Strength Experiment}
To locate the point at which bidirectional search overtakes unidirectional A*, we devised a controlled experiment, where we hold all parameters fixed and gradually weaken the heuristic.

\subsubsection{The weight knob}
We define the weight knob $h'(n)=w\cdot h(n)$, where $w \in [0,1]$.
\begin{itemize}
    \item $w=1$ is the full strength Manhattan/octile heuristic.
    \item $w=0$ is Dijkstra, where all heuristics are 0.
\end{itemize}
Note that $h'$ stays admissible and consistent for all $w \in [0,1]$:
\begin{itemize}
    \item Admissible: $h(n)\le h^*(n)$, and since $w \le 1$ and $h(n)\ge 0$, we get $h'(n) = w \cdot h(n) \le h(n) \le h^*(n)$.
    \item Consistent: from $h(n) \le c(n,n') + h(n')$, multiply by $w \ge 0$ and get $w \cdot h(n) \le w \cdot c(n, n') + w \cdot h(n')$. Since $c(n,n') \ge 0$ and $w \le 1$, we have $w \cdot c(n,n') \le c(n,n')$, which gives $h'(n) \le c(n,n') + h'(n')$.
\end{itemize}
The same $w$ scales $h_F$ and $h_B$, so both directions stay admissible and consistent. As such, every optimal algorithm stays optimal and the floor stays well defined at each $w$. The floor's value depends on $h$, so it moves with $w$. We compare exp/floor only within a fixed $w$, and use raw expansions across $w$.

\subsubsection{Setup}
We set up the experiment so that only one variable moves ($w$). The domain, instances, and algorithms all stay fixed. We run it under 26-connectivity, on one map from each family - plant01, the Parker sandstone sample, and descent level20 - over 80 instances per map taken from the same seeded shuffle as the main sweep, sweeping $w$ over $\{1.0, 0.8, 0.6, 0.5, 0.4\}$. The sweep is denser at the lower end, where the crossover falls. Weakening the heuristic grows the searches quickly, so this experiment uses a 300 s cap per run rather than the 60 s of the main protocol. For each $(w, \text{algorithm})$ we record the median raw node expansions, together with the fraction of instances solved at that weight. We use raw expansions rather than exp/floor, as the floor itself shifts when the heuristic changes.

This experiment varies the scale of the heuristic, and not the structure of its inaccuracy, so it does not test claims about where a heuristic is inaccurate. It covers one map per family and not the full sweep, so we read it as evidence that the behaviour holds across the three structures rather than as a measurement of its size. As coverage falls with $w$ for the slower algorithms, we report each median alongside its coverage, and we do not compare medians across algorithms whose coverage differs by much.

\section{Experimental Results}
The stopping rule took us to 1500 instances per plant map and 500 per sandstone and descent map, drawn in the shuffled order described above. Every median below is taken over solved instances, and the full per-instance data is released with the code.

\subsection{Convergence and exclusions}
We report each median with a bootstrap $95\%$ CI, and we ran each group until that interval was within $\pm3\%$ of its median or we stopped extending it. Most groups converged well inside the target - on descent and sandstone under 6-connectivity every algorithm reached under $2\%$.

Two sets of groups did not converge, and we report them with their wider intervals rather than dropping them. MM failed to converge in every diagonal mode, as it times out on most diagonal instances and its median then rests on the few it solves - its CI there runs from $3.8\%$ to $5.7\%$. On plants under 6-connectivity, NBS, MM and reverse A* are heavy-tailed and reach $8.3\%$, $10.6\%$ and $9.0\%$ respectively. NBS and reverse A* are not timeout-limited there, so a further round might have brought them inside the target. We stopped at two rounds to stay inside our compute budget. Note that no group used all 2000 instances available to it. The sample sizes are the ones the stopping rule reached, as the previous section describes, and MM is short of the target in every 26-connected group.

Where that holds, a bidirectional score is close to a ratio against A*'s own contour rather than against an independent minimum. The second is that the bound is not tight for A* either, in the other direction. Its median is $1.00$ but its mean reaches $28.8$ on plants under 26-connectivity and $240.9$ on sandstone under 6-connectivity, with a maximum over $3\times10^5$. So the bound is close to A*'s contour on most instances and very loose on a minority, and neither the median nor the mean alone describes it.


\subsubsection{How far each algorithm sits}
Excluding MM, the bidirectional algorithms sit between $0.95$ and $1.7$ times the bound on the diagonal maps. BiA* and NBS hold a narrow band there, $1.54$ to $1.69$, and BAE* is the one that ranges lower, from $1.57$ down to $0.95$ on sandstone. Our own first pass measured that premium at $2$ to $6$ times. That pass read the leading instances of each scenario file, and those files are difficulty-graded \cite{nobes2023voxel}, so its sample was systematically easy. We report the difference because it is what the shuffled sampling changed.

Every bidirectional algorithm drops below the bound on some instances, but for most of them this is a tail and not a median. Only one cell of the table is below 1, BAE* on sandstone under 26-connectivity at $0.95$. Elsewhere BiA* falls below on $0\%$ to $2\%$ of a group's instances, NBS on $0\%$ to $1.3\%$ and MM on $0\%$ to $0.6\%$, against $0.6\%$ to $55.6\%$ for BAE*. So the medians in the table are the honest summary, and the sub-bound cases sit underneath them.

How far the tail reaches differs sharply by algorithm. BiA* falls to $0.066$ on $571$ of its $46{,}812$ solved instances, NBS to $0.377$ on $297$ and BAE* to $0.019$ on $10{,}385$. MM only reaches $0.976$ on $73$, and that gap between MM and the rest is what the next paragraphs turn on.


\subsubsection{Why some scores fall below the floor}
For two of the four the reason is the one the Methodology gives, that an algorithm whose correctness rests on consistency sits outside the class the bound covers. BAE* is that case through its error term and our BiA* through the rule we added, and \citet{eckerle2017sufficient} name BS* \cite{kwa1989bs} as the same case and leave it as future work. Neither is a violation, and neither is the interesting one.

NBS and MM are not candidates for that explanation as published. \citet{eckerle2017sufficient} present NBS as an admissible DXBB algorithm and describe MM as admissible, so the bound applies to both. The implementations we run are not quite those two algorithms, and that difference accounts for most of what follows.


\subsubsection{MM and the $\varepsilon$-refined graph}
MM sits just below the floor, and the gap is a difference of definition rather than a saving. HOG2 implements MMe, the variant of \citet{holte2017mm} that expands on $max(f, 2g+\varepsilon)$ where $\varepsilon$ is a lower bound on the edge costs, fixed at $1$ in our build. MMe expands the candidates with $g < (C^*-\varepsilon)/2$, while our floor is the threshold cover at $\tau=C^*/2$, computed from the must-expand condition without the $\varepsilon$ refinement that \citet{shaham2018consistent} provide. The shortfall is therefore the band of nodes whose $g$ falls between $(C^*-1)/2$ and $C^*/2$, and it is deterministic rather than incidental. Its $73$ cases bear this out, as the worst is $0.976$ and the median is $0.998$. On that worst case, a diagonal plant instance, the band holds $228$ forward and $224$ backward candidates against an observed shortfall of $447$ nodes, or $2.4\%$. The dips are wider on the diagonal maps, at $0.976$ against $0.9949$ on the integer-cost maps, and that follows from the same mechanism. Under 6-connectivity every $g$ is an integer, so a band of width one half is almost empty, while the incommensurable costs of 26-connectivity fill it. These cases are a loose denominator and not an excursion below the bound.


\subsubsection{NBS, and two populations}
NBS splits into two groups with two different causes, and the $\varepsilon$ shell sets the boundary between them. Its $297$ cases reach $0.377$ with a median of $0.913$, and $290$ of them sit on descent maps, with $4$ on plants and $3$ on sandstone.

A minority of them have the same cause as MM's. NBS also commits to the $\varepsilon$-refined must-expand graph, as its queue adds $\varepsilon=1$ to the pair bound before comparing it against the incumbent, while our floor applies no such refinement. On a diagonal plant instance scoring $0.980$ the refined cover holds $12{,}553$ vertices against $12{,}845$ for the unrefined one, and NBS expands $12{,}588$. It therefore covers in full the graph it actually commits to, and its shortfall against our floor is the $\varepsilon$ shell of $292$ vertices, or $2.3\%$. The shell is what caps this explanation. Across our instances it never exceeds $2.4\%$, so it can only account for cases within that distance of the floor, and there are $105$ of those with a median of $0.9969$. They are a loose denominator rather than a saving.

The other $192$ fall further than the shell can reach. Their median is $0.826$ and they run down to $0.377$, so no refinement of a few percent explains them.


\subsubsection{Isolating the rule}
Two candidates for them sit in the implementation rather than in the published algorithm, and a rebuild separates the two. The first is a rule that discards a generated node already closed on the opposite frontier, which HOG2 compiles unless \texttt{ADMISSIBLE} is defined and which our build leaves undefined. That is the same consistency-exploiting rule we added to our own BiA*, and it places NBS outside the class for the same reason. The rule is not new, and naming it locates all of this in the literature. It is the nipping of \citet{kwa1989bs}, and BS* is the algorithm \citet{eckerle2017sufficient} name when they set aside algorithms that rely on consistency. \citet{holte2017mm} make the same point from the other side, observing that an algorithm which meets in the middle needs neither consistent heuristics nor special mechanisms such as Kwa's nipping and pruning. So the theory anticipated this case, and what we add is that a current implementation of an in-class algorithm quietly contains it. The second is its termination, which can fire once its lower bound reaches the incumbent and need not wait until the must-expand pairs are covered. Defining the flag disables the first and leaves the second, so a comparison of the two builds isolates the discard.

We ran that comparison on twenty-four instances, drawn from four map and movement-model groups so that neither the geometry nor the cost model is held fixed. Twelve are the deepest cases, diagonal instances of one descent level over covers of $4.5$ to $9.3$ million vertices, where the default build scores $0.377$ to $0.493$. The other twelve cover a 6-connected descent level that alone holds $127$ of the $192$, a second diagonal level, and a second 6-connected one, where the default build scores $0.574$ to $0.834$. On all twenty-four the admissible build lands above the floor, between $1.11$ and $1.47$, and both builds return the same optimal cost on every instance. There are no exceptions. The discard is therefore the mechanism, and it is an efficiency that consistency permits rather than a correctness fault, which is why it never shows up as a wrong answer.

A second argument reaches the same conclusion without the rebuild. The $\varepsilon$ shell can be measured directly, and on the 6-connected instances above it never exceeds $0.25\%$ of the cover, as integer costs leave the half-unit band nearly empty, while on three of them it is exactly zero. Those same instances sit $17$ to $43\%$ below the floor. A shell two orders of magnitude too small cannot account for that shortfall, so these cases are not a denominator artifact even before the flag is set.

The counts show why so small a rule moves so much. Across the twenty-four the discard fires between $732$ and $148{,}064$ times, while the expansions it saves run from $1.2$ to $8.5$ million, two to three orders of magnitude more. Each discarded node sits at the root of a subtree that is then never generated, so how high in the search it sits sets the amplification, and that varies from $40$ to $2455$ times rather than holding at any one figure. The 6-connected instances make the point most sharply, as they nip the fewest nodes and gain the most from each - on one of them $732$ discards account for $1.8$ million expansions.

The flag that controls all of this is undocumented, and the one comment that names it is wrong. It appears twice as a commented-out define, each time with no note of what it does or that leaving it off costs admissibility, and no README or paper in the framework mentions it. The single line of prose that refers to it says the flag is defined in the header where it is in fact commented out. A reader who trusted that line would take the in-class build to be the default, when the shipped default is the opposite. We report this because the rule is sound and the silence is the problem - anyone measuring this implementation against the must-expand bound would compare the two without knowing they differ.

One limit of our own floor audit bears on the deepest of them. The threshold scan is checked against a direct maximum-matching cover on $3000$ random chain graphs, which establishes that the scan returns the true minimum of the graph it is given. The construction of that graph, meaning the two candidate contours and $C^*$, is audited directly on a plant instance and not on a descent one. As such the part of the floor we have not checked in place is the part the deepest cases rest on.

The bound is tight for A* and loose for the others, so a straight comparison flatters A*. Separating the instances by how much room the bound actually claims removes that advantage. \subsubsection{NBS against its own factor of two}
One number in Table~\ref{tab:expfloor} looks like a violation and is not. NBS's median on plants under 6-connectivity is $3.41$, above the factor of two it guarantees, and it clears twice the cover on $84\%$ of that group rather than on a tail. The guarantee is narrower than the ratio we report. \citet{chen2017nbs} build the must-expand graph from pairs with $lb(U,V)<C^*$ strictly, and their Theorem 3 bounds only the expansions NBS makes in covering those pairs. Expansions at $f=C^*$ fall outside that accounting, and they note that NBS may make many of them where another algorithm does not. Our exp/floor puts that whole plateau in the numerator and none of it in the denominator. The cover is not undersized here, as A* sits at $1.06$ on the same instances, and NBS expands $2.42$ times what A* does per instance at the median. Note that $83.4\%$ of this family's 6-connected instances have $\text{MVC}=0$ and are excluded from this axis, so that share is evidence about the family and not about this median. Manhattan is exact end to end on most of these instances, and on the ones that remain it is still exact over the open floor, so the $f=C^*$ plateau is large. \citet{chen2017nbs} report the same mechanism on the pancake puzzle under the GAP heuristic, where the heuristic is often perfect and expansions concentrate at $f=C^*$.

One caution on coverage goes beyond the table markers. Every bidirectional algorithm has a non-trivial diagonal timeout rate, so all of their medians are over solved instances and are mildly optimistic, BAE* included.

\subsection{(B) Time}
A* is the fastest algorithm in every diagonal configuration, and the bidirectional algorithms cost it roughly $1.6$ to $3.3$ times in wall-clock time there. It is not fastest everywhere. On plants under 6-connectivity BiA* runs at a median of $1.6$ ms against A*'s $1.9$ ms, over the full sample that both solve, and it also expands fewer nodes at the median. MM's $1.8$ s median on sandstone under 26-connectivity is below A*'s $3.3$ s, but that is survivorship rather than speed, as MM solves $116$ of $5{,}500$ there against A*'s full sample. Per expansion the gap is much smaller - A* runs at $1.9$ to $2.7\,\mu$s on diagonal maps, against $2.8$ to $3.9\,\mu$s for BiA* and NBS and $3.7$ to $4.6\,\mu$s for BAE*. As such, most of the wall-clock difference comes from expanding more nodes and not from a dearer node.

MM is the exception, and it pays on both counts. Its per-expansion cost on diagonal maps runs from $8.4$ to $19.6\,\mu$s, four to seven times A*'s, and it also expands more nodes. Note that MM's per-expansion median pooled over all groups looks low at $1.4\,\mu$s. That is survivorship - the figure is dominated by the 6-connected groups, where it solves everything and the searches are small.

That constant is not a property of the algorithm, and locating it changes how the robustness result below should be read. HOG2's MM keeps its open nodes in a histogram bucketed by $(g,h)$ and recomputes the termination bound by iterating that histogram on every expansion, which costs the number of distinct buckets rather than the logarithmic cost of a heap. The implementation carries its own note that this should be made more efficient. The cost of the scan is set by how many distinct $g$ values the open list holds, and that is where the cost model enters. On a diagonal plant instance a forward contour of $19{,}379$ nodes holds $14{,}497$ distinct $g$ values, as sums of $1$, $\sqrt{2}$ and $\sqrt{3}$ rarely coincide. Under 6-connectivity the same contour holds a few hundred, as every $g$ is an integer bounded by $C^*$. The honest statement is therefore narrower than the one we first drew - MM as HOG2 implements it cannot finish these instances, and the reason is an implementation whose per-node cost scales with the number of distinct $g$ values that this cost model produces. This is still a theory-against-practice result, and it is a sharper one than a budget artifact, as it says where the gap between the two actually sits. MM is designed to bound its expansions and it does. What defeats it here is the cost of proving it may stop.

\subsection{(D) Direction}
Reverse A* expands between $1.35$ and $3.04$ times the bound where forward A* sits at $1.00$ to $1.06$. Note that this is largely a property of the benchmark and not a discovery about the domain. \citet{nobes2023voxel} rank each instance by the cheaper of its two search directions, measured in A* expansions, and then output it in that orientation, so forward search is the easier direction by construction on all three families. Their Figure 5 states that the three families we use were designed to control for the direction of bias. We therefore measure the size of that built-in orientation under our heuristic and cost model, and not whether it exists. Figure~\ref{fig:asym} compares the two directions directly, as the median of the per-instance ratio rather than a ratio of the two medians. Read that way the effect is smaller than Table~\ref{tab:expfloor} suggests, at $1.35$ to $1.72$ times, and plants under 6-connectivity sits at exactly $1.000$. That figure is a straddle and not a plateau. On that group $32.9\%$ of instances have reverse expanding fewer nodes than forward, $17.9\%$ land exactly on parity, and $49.1\%$ sit above it, so the cumulative distribution crosses one half inside the spike at $1.0$. An exact heuristic is not the explanation, as $83.4\%$ of this group has $\text{MVC}=0$ while only $17.9\%$ expands equally in both directions. What the median conceals is the tail, which is severe. The same ratio reaches $12$ at the 75th percentile, $102$ at the 90th and over $3000$ at the 99th, and that tail is what separates the two floor-relative medians of Table~\ref{tab:expfloor} by a factor of three. We report both, as the per-instance median says what a typical instance costs while the floor-relative figure says how heavy the tail is.

We do not draw a family-level conclusion from it. The main sweep gives us the same ratio at full strength on every map, and it varies as much within a family as between them - across the five plant maps it runs from $1.03$ to $2.28$, and across the descent levels from $0.90$ to $2.12$. Note that those figures come from the main sweep, so plant01 reads $1.14$ there against $1.04$ in Table~\ref{tab:xover} - the two runs use different samples and different caps, and we do not treat the difference as a result. MM collapses on all three maps. Below full strength it solves $0$ to $3$ of $80$ instances, and $0$ of $80$ on level20. It does not overtake anything under a weakened heuristic - it stops being usable. Note that this does not test the MM0 comparison from the literature review, as weakening the heuristic is not the same as removing it, and we did not run MM0. An earlier run on six instances appeared to show MM overtaking A* - that result rested on a single solved instance, and we retract it.

BiA* and NBS never overtake A* at any weight. As such, the advantage this experiment shows belongs to the error-exploiting method rather than to meet-in-the-middle. Note that we compare raw expansions here rather than exp/floor, as the bound moves with $w$.

\subsection{GBFS as a speed and quality reference}
GBFS is not cost-optimal, so the bound does not apply to it and we report it separately. Pooled over the sweep its median solution cost is $1.337$ times $C^*$ and its median expansion count is $27{,}655$. The quality penalty varies widely by group, from $1.03$ times $C^*$ on plants under 26-connectivity to $2.14$ on sandstone under 6-connectivity, so the pooled figure understates how poor its paths become on the harder groups. It is the fastest way we have to get a path and the worst path we report. That is the trade it exists to illustrate.

\subsection{Correctness}
The optimal algorithms agree on cost everywhere. Across every group, A*, reverse A*, MM, BiA*, BAE* and NBS return identical costs on every instance all of them solved, with no wrong-cost result anywhere in the sweep. Note that for MM on diagonal maps this covers only the small fraction it solves.

Our legality audit was run on an earlier subset and not on the representative sample, and we report it as such. It found no illegal move in roughly 1.8M generated successors and 58k path edges. The move rule and the successor generator did not change between the two runs, so the legality conclusion carries over even though the counts are not from this sample.

\section{Conclusions and Summary}
We set out to measure how close bidirectional search comes to a provable floor on 3D voxel maps, and to find where its theoretical efficiency translates into practical performance. The floor is the main instrument, computed per instance at contour sizes that need the threshold form rather than the explicit graph. On this domain the theory and the practice come apart more than the theory alone suggests, and the clearest cases are negative.

Against the must-expand floor, A* is the algorithm to beat and it is hard to beat. Its median sits within $6\%$ of the bound in every configuration, and BiA* and NBS hold a band of $1.5$ to $1.7$ times the bound on the diagonal maps. That band is a good result rather than a poor one, as no algorithm of this class has a worst case better than twice the bound, and the bound itself is reached only by an algorithm given a parameter it cannot know in advance. Note that the floor tracks A*'s own contour on most instances, as the two agree to within $2.7\%$ across the diagonal groups, and it departs from A* only on the minority where the bound claims real room. That minority is where the comparison does independent work. On the $1{,}311$ instances where A* is at least twice the floor, A* sits at $6.13$ and BiA* at $3.53$, so BiA* is closer to the bound than A* is exactly where there is room to be.

BAE* comes closest to A*, and it is the only algorithm that overtakes it. As the heuristic weakens, BAE* ends below A* on two of the three maps we swept, crossing over on one. That is the direction the theory predicts. We do not read it as a family-level result, as the ratio varies as much within a family as between them, so we report the trend per map and claim no more.

MM is the sharpest case of theory failing to translate, and tracing why turned it into a second instance of the same finding. It is designed to bound its expansions and it does, yet on the diagonal maps it cannot finish the instance at all. It times out on $77$ to $98$ percent of them, and five times the budget still leaves it solving $0$ to $2$ percent, so the collapse is not an artifact of our cap. The cause is not the number of nodes it expands, which is only two to three times A*'s. It is the cost of each expansion, and that cost is an implementation choice meeting our cost model badly. HOG2's MM recomputes its termination bound by scanning a histogram of open nodes keyed on $g$, and under 26-connectivity the incommensurable costs give a contour of nineteen thousand nodes over fourteen thousand distinct $g$ values, where 6-connectivity gives a few hundred. As such MM's collapse and BAE*'s silent suboptimality are the same lesson twice, and neither is visible until the move costs stop sharing a common measure.

The domain difference is not only a matter of larger maps or higher branching. HOG2's BAE* tightens its termination bound by rounding to the greatest common divisor of the edge costs, which is correct on integer-cost domains. Our 26-connected costs $\{1, \sqrt{2}, \sqrt{3}\}$ share no common measure, so the tightening cannot be applied at all. At its default the bound was inflated and BAE* returned suboptimal paths, silently, and we caught it only through an external cost oracle. This is concrete evidence that a framework calibrated on unit-cost and puzzle domains does not carry over to voxel maps unchanged.

NBS falls below the floor on $297$ instances, and they divide into two causes rather than one. NBS commits to the must-expand graph refined by a unit lower bound on edge cost, while our floor applies no such refinement, so we score it against a slightly larger cover than the one it actually has to meet. That gap is a shell of at most $2.4\%$, and it accounts for the $105$ cases that sit within that distance of the floor. The remaining $192$ fall further than the shell can reach, with a median of $0.826$ and a minimum of $0.377$, so a refinement of a few percent does not explain them.

Those we traced to a rule in HOG2's NBS that discards a generated node already closed on the opposite frontier, which is the same rule that places our own BiA* outside the bound's class. On twenty-four instances spanning three descent levels and both movement models, disabling it by defining \texttt{ADMISSIBLE} lifts NBS from between $0.38$ and $0.83$ times the floor to between $1.11$ and $1.47$, above the floor on every one, with the optimal cost unchanged. So NBS as HOG2 builds it is not in the class the bound covers, while the admissible build is and sits above the floor as the theory requires. The lesson generalises past NBS. Three of the four algorithms we took from this framework differ from their published forms in ways that change what the bound says about them, and none of the three differences is announced anywhere the user of the library would see it.

One limit of our own work bears on the deepest of these cases. The scan that computes the floor is verified against a direct minimum cover on random graphs, but the graph it is built from was audited on a plant instance and not on a descent one, and these rest on descent.

Two cautions carry beyond this paper. The scenario files are difficulty-graded, so any prefix of them is systematically easy, and correcting for it by shuffling moved our own headline figure by roughly three times. The benchmark also writes each instance in its cheaper search direction, so a forward advantage is built into the data rather than found in it.

The results come with real limits. Every median is taken over solved instances, so all are optimistic, and most so for MM, which solves the fewest. On plants under 6-connectivity the heuristic is exact on $83.4\%$ of instances, so the floor axis there speaks for only $1{,}247$ of $7{,}500$. The heuristic-strength experiment covers one map per family rather than the full sweep, and the legality audit ran on an earlier subset than the reported sample. We report each limit next to the number it qualifies rather than in a separate caveat.

For future work, MM is worth re-running against an implementation that maintains its termination bound incrementally, which would separate the algorithm from the cost of proving it may stop. Widening the heuristic-strength sweep to several maps per family would settle whether BAE*'s crossover is a property of the geometry or of the maps we happened to choose.

\section{Appendix B: Run accounting}
The cap binds a small tail. We sampled $27{,}500$ instances per movement model - $1500$ on each of the five plant maps and $500$ on each of the eleven sandstone and twenty-nine descent maps - and ran seven algorithms on each, so $385{,}000$ runs were planned. Of those, $742$ never ran, as the $106$ descent instances noted above did not finish inside the cluster's allocation, and a further $35$ runs on those same two levels are missing from the log. That leaves $384{,}223$ records. Our raw log also contained four rows where a run that finished was additionally recorded as a timeout, from a race in the run harness that we have since fixed, and the data we report excludes them. Those rows never entered any median, as we compute expansions, ratios, time and memory over solved runs only, and dropping them moves one reported figure by $0.01$ percentage points. Of the records, $302{,}358$ are solved, $27{,}015$ timed out and $54{,}850$ are GBFS runs, which we record as suboptimal rather than solved as GBFS is not cost-optimal. GBFS accounts for $36$ of the timeouts as well, so every suboptimal record is a GBFS run while not every GBFS run is suboptimal. Across the solved runs the median wall time is $3.0$ s, the 99th percentile is $38.4$ s and the 99.9th is $54.3$ s, so the 60 s cap sits at roughly $1.6$ times the 99th percentile and $235$ solved runs finish within 5 s of it. \section{Appendix C: The threshold cover}
Let $S_\tau = \{u_F \in L : g_F(u) < \tau\} \cup \{v_B \in R : g_B(v) < C^*-\tau\}$. The union is disjoint, as it is taken over the two separate copies, so $|S_\tau| = N_F(\tau) + N_B(C^*-\tau)$. We will now show that $S_\tau$ is a valid vertex cover for every $\tau$, so that $\min_\tau|S_\tau|$ is an upper bound on the MVC. That this bound is tight - that some threshold cover attains the minimum - we take from \citealt{shaham2018consistent}, and do not reprove:
\begin{itemize}
    \item Valid cover - for any edge $(u,v)$ we have $g_F(u)+g_B(v)<C^*$. If neither endpoint were in $S_\tau$, then $g_F(u)\ge\tau$ and $g_B(v)\ge C^*-\tau$, summing to $\ge C^*$, a contradiction. So $S_\tau$ covers every edge, for any $\tau$.
    \item Tightness - once we restrict to the two $f<C^*$ contours, the only edge condition left is $g_F(u)+g_B(v)<C^*$, so the forward neighbourhoods are ordered by inclusion. \citet{shaham2018consistent} and \citet{shaham2017minimal} before them show that some threshold cover attains the MVC once the neighbourhoods are ordered this way, which gives $\min_\tau|S_\tau| = \text{MVC}$. The result is \citet{shaham2017minimal}'s, and \citet{shaham2018consistent} restate it in a form valid for any non-negative $\varepsilon$, including the $\varepsilon=0$ case we use. This is the direction our reported floor rests on, and we take it as given without reproving it. Note that consistency is why the $g$ values in the edge condition are the instance's optimal distances. We also checked the scan itself against a direct minimum vertex cover computed by maximum matching, over $3000$ random chain graphs, and the two agreed on every one. As the restricted graph is a chain graph, this confirms the scan returns the exact minimum cover and not merely an upper bound on it. We also audited the floor directly on the instance where the closest algorithm to it came in furthest below, a diagonal plant instance on which MM scored $0.976$. The forward and backward candidate sets there match what A* and reverse A* expand to within four nodes out of roughly twenty thousand, so the contours are not over-collected, and $C^*$ agrees between the floor binary and the measured run. The scan's value is the minimum over every breakpoint and not a local one. The floor on that instance is the exact minimum cover.
\end{itemize}

\section{Appendix D: Correctness checks}
To make our results trustworthy, we must not only assert optimality - we must also verify it. This was done in three ways:
\begin{enumerate}
    \item An independent auditor re-implements the move rule from scratch, sharing no code with the environment's own move test, and verifies that both the successor generator and every returned path only contain legal non-corner-cutting moves - adjacency, both endpoints free, and every voxel a diagonal move clips free.
    \item In 26-connectivity we verify every returned cost against the reference optimal cost in the \texttt{.3dscen} file, to within $10^{-2}$. Note that we rejected that same value for computing $C^*$ because it is too coarse for the strict comparisons the bound needs. It is still useful here, as this check looks for gross error rather than boundary classification, and a wrong cost would miss by far more than $10^{-2}$. This is an oracle external to our implementation, which agreement between our own algorithms cannot give us. It is not available in 6-connectivity, as the reference costs are computed with diagonals and do not apply there.
    \item In both modes we verify that all optimal algorithms agree on the $C^*$ value, to within $10^{-2}$. In 6-connectivity this is the only optimality check we have. Note that this check is what localised the BAE* defect described above, as BAE* was the only optimal algorithm returning a cost the others did not. We leave GBFS out of it throughout, as it is not guaranteed to return an optimal solution.
\end{enumerate}
All three checks passed on the runs they cover. Note that the legality audit covers an earlier subset rather than the representative sample, and we report the counts and the coverage of each check with the results.
