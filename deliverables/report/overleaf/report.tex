\begin{abstract} Bidirectional search is meant to beat A* by working from both ends at once. On hard domains it often does not, and it is hard to say why when your only yardstick is another algorithm. We therefore measure against a fixed reference: for each instance, the number of expansions any correct front-to-end search must make. We run seven algorithms against it on three families of 3D voxel maps, under two movement models, one stepping along the axes only and one allowing diagonal steps as well.

The first answer is that there is little room to begin with. A*'s median sits within $6\%$ of the bound in every configuration, and BiA* and NBS hold a band of $1.5$ to $1.7$ times it.

The second was not what we went looking for. In three of the four algorithms we took from HOG2, implementation and algorithm come apart in ways that change what the bound says. BAE* tightens its termination test by rounding to a common divisor of the edge costs, which the diagonal costs do not have, so it returns suboptimal paths with no error raised. NBS compiles a node-discarding rule that is sound only under a consistent heuristic and takes it outside the class the bound covers. Switching it off lifts its worst instances from $0.38$ to $1.29$ times the bound. MM cannot finish $77$ to $98$ percent of the harder instances, and the cause is what each expansion costs rather than how many it makes.

None of the three differences is documented, and none of them announces itself when the code runs. We found them because a fixed bound gives an implementation something it can visibly fail against, which comparing algorithms with each other does not.
\end{abstract}

\section{Introduction}

Pathfinding is one of the most fundamental problems in artificial intelligence and in navigation systems.

The goal is to find the lowest cost path between a start node and a goal node. Finding an optimal path is challenging and may require exploring many nodes.

One approach to reduce the number of nodes a search must expand is bidirectional search~\cite{pohl1971bidirectional}. Instead of searching only from the start, we interleave a forward search from the start with a backward search from the goal, and continue until the algorithm can guarantee that the best path found is optimal. The saving is in the volume each search covers and not in the length of the path.

\subsection{Motivation}

Even though bidirectional search seems like a promising approach, it is not always better than a unidirectional algorithm such as A*. With the right heuristic A* moves toward the goal quickly and avoids expanding unnecessary nodes, and bidirectional search has long been observed to lose to it when the heuristic is strong~\cite{barker2015limitations}.

Additionally, bidirectional search must decide which side to continue, which node to expand, and when the best path found is guaranteed to be optimal. Those three decisions are what the algorithms in this paper differ on.

To measure an algorithm we need a baseline to measure it against. Comparing algorithms only to each other is relative, as they might all sit far from what the problem actually requires. For bidirectional search there is a stronger option. The literature gives a per-instance lower bound on the number of expansions any correct front-to-end algorithm must make, and we can compute it. Every number in this paper is a distance from that bound rather than a distance from a rival. The Literature Review sets out where the bound comes from, and the Methodology how we compute it.

The domain is where measuring against that bound becomes interesting. The must-expand theory was developed and evaluated on unit-cost grids and on permutation puzzles. 3D voxel maps differ from both in the three ways the theory is most sensitive to. A voxel has 26 neighbors rather than 8, the move costs are $1$, $\sqrt{2}$ and $\sqrt{3}$ and share no common divisor, and the maps run to roughly $1.3$ billion voxels. Each of those costs us something later. A contour, throughout this paper, is the set of nodes a search has to look at before it can prove that the path it has found is the cheapest one. The branching factor widens the contours the bound is defined over, the costs break an assumption that two of the implementations we test rely on, and the size rules out building that graph at all, so the bound has to be computed in a form that never constructs it. Whether that difference is merely nominal is a fair question to ask before spending a project on it, and the answer is no. A published implementation of one of the algorithms we run returns suboptimal paths on this cost model, silently, for reasons we set out in the Methodology.

\subsection{Research Goal}

The goal of this project is to measure how close bidirectional search comes to that bound on 3D voxel maps, and to find where the gap between the two widens. We run seven algorithms - A*, reverse A*, MM, NBS, BAE*, BiA* and GBFS as a deliberately suboptimal reference - on the three voxel families of \citet{nobes2023voxel}, under both movement models, with A* run from each end.

Two questions organize what follows. The first is how close these algorithms come to the bound, and whether getting close translates into practical performance. That one was answered quickly, as a strong heuristic leaves a small gap to begin with and the bidirectional algorithms close part of it. The second question was raised by the first and took the rest of the work. Several algorithms scored below a bound that no correct algorithm of their class can beat, and accounting for that meant reading the implementations rather than the papers.

We report each algorithm along five axes: expansions against the floor, time, memory and robustness, direction, and the response to a weakened heuristic. We measure rather than rank, and where two algorithms separate by less than the uncertainty in our own measurements we report both and rank neither. The sweep runs under both movement models, 26-connectivity with diagonal moves and 6-connectivity without, and we treat the two as equal cases rather than one as a supplement to the other.

We claim four contributions. The first is the measurement itself, as the must-expand floor has not previously been computed per instance on this domain, and at these sizes it cannot be computed by building the graph it is defined over, only by counting across it. The second is that the gap between a published algorithm and a widely used implementation of it is where this domain does its damage. In BAE*, NBS and MM, three of the four algorithms we took from HOG2, the implementation and the algorithm come apart in ways that change what the bound says about them, and none of the differences are announced to anyone using the library. The third is an account of every score we record below the floor, settling by experiment which are a loose denominator and which are a genuine escape from the class the bound covers. The fourth is a caution about the benchmark, whose difficulty-graded scenario files moved our own headline figure by roughly three times. The Conclusions state each one in the form the results support.

\section{Literature Review}

\subsection{When bidirectional search loses}
Bidirectional search is an old idea. \citet{pohl1971bidirectional} searches forward from the start and backward from the goal at once. The argument for it is about volume rather than about path length. A single search of depth $d$ explores on the order of $b^d$ nodes, where $b$ is the branching factor, while two searches of depth $d/2$ explore on the order of $2b^{d/2}$. This is a brute-force argument. It says nothing about what happens once a heuristic guides the search.

Once a heuristic guides the search, most of that saving disappears. Bidirectional search has long been observed to lose to A* when the heuristic is strong~\cite{barker2015limitations}. To see why, write $C^*$ for the cost of an optimal solution, and $f(n) = g(n) + h(n)$ for the usual estimate of the cost of a solution through $n$, where $g$ is the cost of reaching $n$ and $h$ estimates the cost of finishing from it. A* with a consistent heuristic expands exactly the nodes with $f < C^*$, and is optimally efficient over that set~\cite{hart1968astar, dechter1985generalized}, so a strong heuristic already prunes most of what a second frontier was meant to save.

The reason is structural. A bidirectional search carries two heuristics, one for each direction, and in a front-to-end search each of them aims at the opposite root rather than at the frontier coming the other way~\cite{kaindl1997reconsidered}. The two frontiers therefore tend to pass through each other instead of meeting. Everything that follows in this section is an attempt to say how much a bidirectional search can save. The bound we measure against is defined for that front-to-end class.

\subsection{Meeting in the middle}
\citet{holte2017mm} introduced MM, a bidirectional heuristic search algorithm that is guaranteed to meet in the middle. It is a direct answer to the frontiers passing through each other. The earlier bidirectional algorithms do not guarantee that the two searches meet in the middle, so they can expand many unnecessary nodes, and a bidirectional search can lose the advantage it was meant to have.

For the forward search MM does not order on $f(n)$ alone. It uses the priority function \[pr_F = \max(f_F(n), 2g_F(n))\] where $g_F(n)$ is the cost of the path from the start to $n$, $h_F(n)$ is the estimated cost from $n$ to the goal, and $f_F(n) = g_F(n) + h_F(n)$ as usual. The backward search mirrors it, with $g_B(n)$ the cost from $n$ to the goal, $h_B(n)$ the estimate from $n$ to the start, and $f_B(n) = g_B(n) + h_B(n)$.

The backward search uses the same priority function but starts from the goal and searches in the opposite direction. MM then compares the lowest priority node on each side and expands the one with the lower priority.

The two terms do different work. $f(n)$ guides the search towards the goal, while $2g(n)$ limits how far either side may travel. Note that if $g(n) > C^*/2$ then $2g(n) > C^*$, so $pr(n) > C^*$. Any node past the halfway point therefore carries a priority above $C^*$. As MM always expands the lowest priority available, and as an unfinished search always leaves at least one node of the optimal path with a priority of at most $C^*$, it prefers that node over anything past the halfway point.

MM keeps $U$, the cost of the best solution found so far. Each time the two searches connect, it compares the new solution to $U$ and updates $U$ if the new one is cheaper. It stops once $U$ reaches the lower bound, as no cheaper solution can exist beyond that point.

To summarize, MM guarantees that neither side expands a node with $g(n) > C^*/2$, so the two searches do meet in the middle. This is a guarantee about where they meet and not about cost. It does not follow that MM expands fewer nodes or runs faster than other algorithms. \citet{holte2017mm} report that MM0, the brute-force version that sets $h(n) = 0$ for every node, can expand fewer nodes than MM when the heuristic is weak. That is an empirical finding on their domains and not a general law. MM is one of the seven algorithms we run, and its guarantee is what our robustness axis tests.

\subsection{Must-expand pairs}
Later research moved the focus from where two searches meet to which node expansions any algorithm needs in order to return an optimal solution.

That is what \citet{eckerle2017sufficient} did, by identifying pairs $(u,v)$, where $u$ is a forward-frontier node and $v$ a backward-frontier node, of which at least one node must be expanded before an optimal solution can be guaranteed.

They did this by defining a lower bound on the cost of any solution path through the pair, \[lb(u,v) = \max\{f_F(u), f_B(v), g_F(u)+g_B(v)\}.\] The rule follows from it: $(u,v)$ is a must-expand pair if $lb(u,v) < C^*$. This means at least one of the two nodes must be expanded to guarantee an optimal solution.

This is because when $lb(u,v) < C^*$ the algorithm cannot discard the possibility of a path through $u$ and $v$ with cost lower than $C^*$, so it must expand at least one of them.

The work identifies which expansions a bidirectional search cannot avoid, without saying which node of a pair should absorb the cost. An algorithm is free to pick the more expensive of the two. What changes here is the question the field asks, from how to design a better algorithm to what any correct algorithm must do, and that shift is what makes measurement against a fixed floor possible. Our own floor is computed from this pairwise condition. The requirement to expand one node of every such pair does not bind every algorithm, only those that must stay correct when the heuristics are merely admissible rather than consistent. The ones it leaves out explain several of our own results, so we return to the restriction below.

\subsection{The must-expand graph and its minimum cover}
\citet{chen2017nbs} turn the same condition into a graph. Put every forward candidate on one side and every backward candidate on the other, and draw an edge for each must-expand pair. Because an algorithm must expand at least one endpoint of every edge, the set of nodes it expands has to touch every edge, which is exactly a vertex cover of this graph $G_{MX}$. The cheapest an algorithm could possibly be is therefore a minimum vertex cover (MVC) of it. \citet{shaham2017minimal} then studied that graph and its cover.

Building the full $G_{MX}$ is expensive, and \citet{shaham2017minimal} show that it is not necessary. Nodes that share a $g$ value behave identically in the graph, as the edge condition depends on $g$ alone. As such, they can be collapsed into groups. Let $G_F(i)$ be the set of forward nodes with $g_F = i$, and likewise for the backward side. There is an edge between two groups iff $g_F + g_B < C^*$.

In this collapsed graph the MVC takes a simple form. \citet{shaham2017minimal} show that it is determined entirely by one number, the point along the optimal path where the two searches are made to meet. Choosing that meeting point therefore chooses the cover, and an algorithm that could be told where to meet would expand the minimum. That is what $fMM(p)$ does. The parameter $p \in [0,1]$ fixes the meeting point, the forward search may not pass $p \cdot C^*$, and the backward search may not pass $(1-p) \cdot C^*$.

The algorithm uses the priority functions
\begin{align*} pr_F &= \max(f_F(n), g_F(n)/p)\\ pr_B &= \max(f_B(n), g_B(n)/(1-p))
\end{align*}

Each instance therefore has its own optimal $p^*$, and finding it requires knowing $C^*$ and the distribution of nodes in $G_{MX}$ before the instance is solved. Their own experiments show that the best $p$ moves from instance to instance, so the algorithm is more theoretical than practical.

\citet{chen2017nbs} also introduce NBS, which uses the cover directly. At each step NBS takes the pair with the lowest $lb$ and expands both of its endpoints, so it never spends more than two expansions where a minimum cover would spend one. They prove that NBS never expands more than twice the minimum cover, and that it never expands more than twice what any admissible front-to-end algorithm expands on the same instance. Both guarantees count how many nodes NBS expands. The solutions it returns are optimal. Note what the guarantee counts. It counts only the expansions NBS makes in covering the must-expand pairs, the pairs with $lb(u,v) < C^*$ strictly. Nodes with $f = C^*$ are not in any such pair, so expanding them costs NBS nothing against the guarantee, and \citet{chen2017nbs} note that NBS may expand many of those where another algorithm does not. The guarantee can therefore hold on an instance where NBS still expands far more nodes than a rival.

Two further limits follow, and together they set the scale for anything measured against this floor. The first is that no front-to-end algorithm can do better than twice the minimum cover in the worst case, as \citet{shaham2017minimal} show that for every such algorithm there is a graph on which it expands twice as many nodes as the cover contains. The second is that the cover itself is reached only by $fMM$ given the correct $p$, which \citet{shaham2017minimal} show to be the optimal front-to-end bidirectional search.

A factor of two now appears in three separate statements, and they are not the same claim. NBS's guarantee is an upper bound on one algorithm, that it never exceeds twice the cover. The worst-case limit is a lower bound on the whole class, that none of them can promise better than twice the cover, so the factor is not a weakness of NBS's design but the best any such algorithm can offer. Attainability is a third thing again, and it says that reaching the cover exactly, rather than twice it, needs a parameter nobody can know before the instance is solved. The minimum vertex cover of $G_{MX}$ is the quantity we compute for every instance in this paper, and every score we report is an algorithm's expansions divided by it.

\subsection{The class the bound covers}

The requirement to expand one node of every must-expand pair does not bind every algorithm, and the ones it lets through are what explain our own score anomalies later on.

A bidirectional search carries two heuristics, one aimed at the goal and one aimed at the start, so each property they might have comes in a pair. An instance is bi-admissible when neither heuristic overestimates, and bi-consistent when both are also consistent. Every bi-consistent instance is bi-admissible, so the bi-admissible set is the larger of the two.

One word now does two jobs, and the rest of this subsection depends on keeping them apart. A heuristic is admissible when it does not overestimate. An algorithm is called admissible when it returns an optimal solution on every bi-admissible instance, and not merely on the bi-consistent ones. The second is by far the stronger promise, as it has to hold on the larger set.

\citet{eckerle2017sufficient} prove their result for admissible DXBB algorithms. DXBB stands for Deterministic, Expansion-based, Black Box, and names algorithms that make no random choices, proceed by expanding nodes one at a time, and can learn about the graph only by expanding them. Being front-to-end is a separate restriction on top of that, not part of it.

The strength of that promise is what carries the result. Their proof builds an adversary instance that is bi-admissible but need not be bi-consistent, and shows that any algorithm still correct on it must expand a node of every must-expand pair. An algorithm that promises correctness only when the heuristics are consistent is never asked to solve that instance, so the proof says nothing about it, and it is free to expand fewer nodes than the floor.

The floor therefore binds one class of algorithm and not all of them, and an algorithm outside that class may legitimately expand fewer nodes than it. \citet{eckerle2017sufficient} name one such algorithm and leave the case as open work: BS*~\cite{kwa1989bs}, a bidirectional search that discards nodes already settled by the opposite frontier, a device its author called nipping and one we meet again in the results. A second is BAE*, or Bidirectional A* with Error, which \citet{sadhukhan2013bae} gives. It adds to each node's priority a measure of how far the heuristic has been wrong so far. That error term means anything only when the heuristics are consistent, so it needs the same assumption. \citet{alcazar2020unifying} set out the machinery behind it, a family of lower bounds computed for each node separately rather than one bound held globally, which the next subsection takes up. Extending the must-expand theory to cover the consistent case is what \citet{alcazar2021consistent} does, and \citet{siag2023frontToEnd} enumerate the bounds that become available once consistency is assumed.

\subsection{Meeting at a threshold}
Building on the previous limitations and results, \citet{shaham2018consistent} introduced Meet at the Threshold (MT). MT is close to fMM, with one difference - it uses a fixed threshold $\tau$ rather than a fraction $p$ of $C^*$. The forward search does not expand a node with $g_F > \tau$, and the backward search does not expand a node with $g_B > C^* - \tau$. Setting $\tau = pC^*$ makes MT expand the same set of nodes as $fMM(p)$. The difference is that $p$ is a fraction of $C^*$ and so moves with it, while $\tau$ is an absolute depth that does not, which makes it simpler to analyze.

The authors extend the theory to two cases, and each one gives the algorithm extra information to work with.

In the first case the algorithm knows that every edge costs at least $\varepsilon$. That changes the must-expand condition to $g_F(u) + g_B(v) + \varepsilon < C^*$. As a result, some edges are removed from the new $G_{MX}$, which makes the MVC smaller.

They therefore extend MT to MT$_\varepsilon$. A single threshold no longer suffices, as the forward and backward limits now have to leave room for the $\varepsilon$ the sharper condition subtracts, so they are named separately as $\tau_F$ and $\tau_B$ and satisfy $\tau_F + \tau_B + \varepsilon = C^*$ rather than summing to $C^*$. Together they decide which nodes the algorithm expands. With the optimal threshold, it expands the minimum number of nodes.

In the second case the algorithm knows that both heuristics are consistent. Consistency means a heuristic cannot change faster than the true distance, so two nodes whose heuristic values differ a lot must be far apart. That gives a lower bound on the distance between any $u$ and $v$, \[h_C(u,v)=\max\left(|h_F(u)-h_F(v)|,\ |h_B(u)-h_B(v)|\right),\] which is just the larger of the two heuristic gaps. The must-expand condition becomes $g_F(u) + g_B(v) + h_C(u,v) < C^*$. As in the previous case, this can remove edges from $G_{MX}$.

Earlier the cover was fixed by one number, the depth at which the two searches meet. That no longer holds here, as a single threshold cannot describe the cover once the condition depends on the heuristics as well as on $g$. The authors instead group nodes by their $h_F$ and $h_B$ values, so that every node in a group shares the same pair, and give each group its own threshold. On that basis they introduce MTCON, which replaces the single threshold with a function $b(h_F,h_B)$. A forward node is expanded only if $g_F < b(h_F,h_B)$, and a backward node only if $g_B < C^* - b(h_F,h_B)$. Given the correct $b$, MTCON expands the minimum number of necessary nodes. That function is unknown in advance, exactly as the best $p$ is for fMM.

Overall the paper shows that knowing more about an instance, such as a floor on the edge costs or that the heuristics are consistent, reduces the number of expansions that are strictly necessary. Two things from it carry into this paper. The first is that collapsing the graph by $g$ value, as above, leaves enough structure that the cover can be found by scanning a threshold rather than by building $G_{MX}$ at all, which our contour sizes rule out. The second is that both parameters this line of work rests on, the best $p$ for fMM and the function $b$ for MTCON, require knowing the answer before they can be used to find it.

\subsection{Individual bounds and heuristic inaccuracy}
\citet{alcazar2020unifying} take a different approach, building stronger lower bounds from sources such as heuristic inaccuracy. They show that a bound can be defined per node. Write $LB(n)$ for the lower bound on the cost of any solution through $n$. In its simplest form it is just $f(n)$, and the rest of this subsection is about making it larger. Write $C_{lb}$ for the global lower bound on the optimal cost, which is the smallest $LB$ over the nodes still open, since any cheaper solution would have to pass through one of them. Whenever $LB(n) > C_{lb}$ some other open node is more promising, so $n$ is not expanded yet and its expansion is deferred.

To make these individual bounds stronger they use heuristic inaccuracies, which measure the difference between the $g$ value of node $n$ and the heuristic estimate from the opposite direction, $d_x(n) = g_x(n) - h_{\bar{x}}(n)$. That difference raises the lower bound on $n$, which brings it closer to the true solution cost.

They use this difference to build the two KK bounds, named for \citet{kaindl1997reconsidered}. KKAdd adds to a node's own $f$ the smallest $d$ seen in the opposite direction, $KKAdd_x(n) = f_x(n) + \min d_{\bar{x}}$, so it is never weaker than $f$ alone. KKMax instead adds to the node's own $d$ the smallest $f$ from the opposite direction, $KKMax_x(n) = d_x(n) + \min f_{\bar{x}}$. They also define the bidirectional estimate $b_x(n) = f_x(n) + d_x(n)$. This is the value BAE*~\cite{sadhukhan2013bae} expands on. Its error term is meaningful only when the heuristic is consistent, which places it outside the class of the previous subsection, and \citet{alcazar2021consistent} carries the must-expand theory into that consistent case. BAE* is one of the seven algorithms we run, and this machinery is what explains both its scores below the floor and its behavior as the heuristic weakens. \citet{alcazar2020unifying} also introduce two algorithms of their own, DBS and DBBS. DBS is driven by the g-bound, $g_F(u) + g_B(v)$, together with the KK bounds, while DBBS is driven by the b-bound, $f_x(n) + d_x(n)$. Their experiments show that these bounds reduce expansions overall, with BAE* performing best under them and DBS and DBBS ahead on some instances.

\subsection{Connecting must-expand pairs and search bounds}
Two lines of work had been running in parallel. On one side the must-expand pairs theory~\cite{eckerle2017sufficient, shaham2017minimal, shaham2018consistent}, and on the other algorithms driven by search bounds~\cite{kaindl1997reconsidered, alcazar2020unifying}. \citet{siag2023frontToEnd} connect them, by deriving the bounds from the must-expand conditions themselves.

The derivation rests on one observation, applied to a sharper pair bound than the one above. Where consistency is available the pair bound can be written \begin{align*} lb_C(u,v)=\ &g_F(u)+g_B(v)\ +\\ &\max\left(h_F(u)-h_F(v),\ h_B(v)-h_B(u),\ \varepsilon\right),
\end{align*} which is the form \citet{siag2023frontToEnd} work from. The maximum is taken over three terms, and a maximum is at least as large as any one of them, and at least as large as the average of any group of them. Every group of the three therefore gives a lower bound of its own. There are seven such groups: the three terms on their own, the three ways of pairing two of them, and all three together. The three singles recover the g-bound and the two KK bounds that \citet{alcazar2020unifying} had already given. The four remaining groups give the b-bound and three bounds that had not been stated before. \citet{siag2023frontToEnd} label these seven $B_1$ to $B_7$, and on undirected graphs a five-term version of the same pair bound yields ten more, seventeen in all.

They then place those bounds inside a general framework for bidirectional search, built around three decisions. The first is when to stop, and the bound is what proves that the solution already in hand cannot be beaten. The second is which node to expand, where the framework prefers the node that raises the bound fastest. The third is which direction to expand next. They compare three policies, alternating, a cardinality criterion, and Fastest Bound Increase, of which only the last consults the bound.

From the framework they build a family of algorithms they call Targeted Bound. Its $i$th member expands the nodes that raise bound $B_i$ fastest, while still checking all seventeen bounds to decide when to stop. The member driven by the b-bound is the closest of them to BAE*, as the two order nodes on the same value. They part company on termination, as BAE* stops on the b-bound alone while the Targeted Bound member consults all seventeen. They also examine DBBS, which computes its bounds dynamically rather than targeting a fixed one. That can cut expansions, but the computation is not cheap and it costs running time.

Their results bear on what we measure. The b-bound is among the strongest, and when the heuristic is weak another of them overtakes it. DBBS sometimes expands fewer nodes and still finishes slower. And on some domains BAE* comes close to the minimum number of expansions outright, which suggests there is little room left to beat it by choosing a different bound. Note that on this domain we find BAE* going further still, below the floor itself on a large share of instances, which the results take up.

\subsection{Benchmarks for 3D pathfinding}
Comparing these algorithms needs domains to compare them on. \citet{nobes2023voxel} supply three families of 3D voxel maps, chosen so that the geometry differs in ways search is sensitive to - confinement against open volume, and regular structure against irregular. That separation is what makes the set useful here, as the must-expand bound is a statement about the shape of the two contours, one grown from each end, and a contour grows differently in a winding pore than in an open hall. The Methodology describes what each family actually is.

Supplying the maps is only half of it, as the instances matter as much as the geometry. Choosing start and goal at random is not enough, as most random pairs turn out easy. \citet{nobes2023voxel} measure difficulty by the number of nodes A* expands under their voxel heuristic, which is the 26-connected distance, so that a harder instance is one that costs more to solve. They also run A* in the opposite direction on every instance, to check that an instance is not hard only because of the direction it is stated in, and they keep the smaller of the two counts. Note that they then write each instance out in whichever direction produced that smaller count. As such the published orientation is not neutral - forward search is the easier direction by construction, which is what our directional axis has to measure around. From the graded set they publish 2000 instances per map, spread across difficulty levels.

\subsection{Where this leaves us}
This project runs seven of the algorithms above on those benchmarks and measures them against the must-expand floor rather than against each other, scoring each run by the number of nodes it expands divided by that floor. We run both movement models. The 26-connected case, where a voxel has 26 neighbors and edge costs of $1$, $\sqrt{2}$ and $\sqrt{3}$, is the harder setting for this theory, as both the branching factor and the cost structure sit further from the unit-cost grids the theory was developed on. \citet{shaham2017minimal} report a ratio of this kind already, for four algorithms on eight domains and heuristic pairs of 2D grids and puzzles, aggregated over instances and counting only the expansions below $C^*$. What the work above does not give is the per-instance distribution of that ratio, over total expansions, for seven algorithms, on a domain whose move costs share no common measure. Nor does it say where the crossover against A* falls as the heuristic weakens. Both are empirical questions, and this paper asks them.

\section{Methodology}
\subsection{Domain and Algorithms}
\subsubsection{Domain}
For this project, we used the Warthog 3D voxel maps as our main benchmark. The three families we use are introduced by \citet{nobes2023voxel}, in the file format established by \citet{brewer2018voxel}. This benchmark holds two types of files:
\begin{itemize} \item \texttt{.3dmap} - The map file. Holds the grid dimensions and the set of blocked voxels. \item \texttt{.3dscen} - The scenario file. Holds the start/end pair coordinates, as well as a reference optimal cost for each.
\end{itemize} The three families are:
\begin{itemize} \item Industrial plants - process-plant environments built from anonymized layout data, with component geometry replaced by bounding boxes at 10cm resolution. These hold the greatest proportion of traversable space of the three families, mixing large voids with narrow ones. \item Sandstone - micro-CT scans of porous sandstone rock, with winding narrow pores and irregular, non-symmetric natural structure. \item Descent - 3D maze-like levels from the game Descent, dominated by winding corridors and enclosed rooms.
\end{itemize} We used 45 of the 46 maps that \citet{nobes2023voxel} publish: all 5 plant maps, all 11 sandstone maps, and 29 of the 30 descent levels. The one omission is a descent level whose instances did not complete within our cluster allocation. Map sizes range from 3 million voxels up to 1.3 billion. Each map holds a scenario file of 2000 instances, and we run a representative sample of those as described in the sampling and stopping rule subsections below.

\subsubsection{The two movement models}
In this paper we explore the search algorithms within two distinct movement models:
\begin{itemize} \item 6-connectivity (axis aligned) - In this movement model, the only directions the search algorithms are allowed to move in are axis-aligned ($\pm1$ in $x$, $\pm1$ in $y$, $\pm1$ in $z$). In this context, every movement direction holds the same cost of 1 unit. \item 26-connectivity - In this movement model, the search algorithms are allowed to move to any of the 26 neighbors of a certain voxel (including diagonals). In this instance, the cost of each movement aligns with its direction: face (2 of the same x,y,z, the remaining one is $\pm1$) - 1 unit, edge (1 of the same x,y,z, the other two are $\pm1$) - $\sqrt{2}$ units, corner (all of x,y,z are $\pm1$) - $\sqrt{3}$ units. In this mode there is the additional constraint of no corner-cutting in diagonal moves, which follows the benchmark's own move model~\cite{nobes2023voxel}. A diagonal move may not slip past the corner or edge of a blocked voxel. Moving from a voxel $p$ by an offset $d$ is therefore legal only if every voxel in the smallest box with $p$ and $p+d$ at opposite corners is free. For an edge move such as $d=(1,1,0)$ that box is $2\times2\times1$, so we check four voxels: $p$, the target, and the two voxels one step away in $x$ alone and in $y$ alone. For a corner move such as $d=(1,1,1)$ the box is $2\times2\times2$, so we check eight: $p$, the target, three face neighbors and three edge neighbors.
\end{itemize} 
We run both as each changes the branching factor and the heuristic, and with them the search dynamics.

\subsubsection{The heuristic}
Each movement model gets the heuristic that matches its move set, and both are computed from coordinate differences. For 6-connectivity we use Manhattan distance. For 26-connectivity we use the voxel heuristic, which \citet{nobes2023voxel} define as the obstacle-free 26-connected distance, and which is the 3D analog of the 2D octile heuristic~\cite{sturtevant2012benchmarks}. We write $\delta_1 \le \delta_2 \le \delta_3$ for the sorted absolute coordinate differences between $n$ and the target, and define:
\begin{itemize} \item Manhattan: $h(n) = \delta_1 + \delta_2 + \delta_3$. \item Voxel heuristic: $h(n) = \sqrt{3}\,\delta_1 + \sqrt{2}\,(\delta_2-\delta_1) + (\delta_3-\delta_2)$.
\end{itemize} Both heuristics return the exact shortest path cost from $n$ to the target in an obstacle free grid, and that is what makes them admissible and consistent. Removing the obstacles only relaxes the problem, so the obstacle free cost can never exceed the true cost, which is admissibility~\cite{pearl1984heuristics}. For consistency, write $D(u,v)$ for the obstacle free distance between two voxels, so that $h(n) = D(n,t)$ for the target $t$. As $D$ measures shortest paths, a detour through a neighbor $n'$ can never beat going straight to the target, which is the triangle inequality. A single move also costs exactly its own obstacle free distance, so $D(n,n') = c(n,n')$. Putting those together, \[h(n) = D(n,t) \le D(n,n') + D(n',t) = c(n,n') + h(n'),\] which is the consistency condition.

We rely on consistency again later. It is what lets us compute the must-expand bound in threshold form, it is why a node's $g$ value is optimal when it is first expanded, and it is what decides which algorithms the bound covers, a point we return to below.

\subsubsection{The algorithms}
In this paper we explore seven algorithms and run them against the same benchmark:
\begin{itemize} 
    \item A* - The classic A* algorithm as outlined in \citealt{hart1968astar}. 
    \item Reverse A* - The same classic A* algorithm~\cite{hart1968astar}, but we start from the goal and progress towards the start. It is not a distinct algorithm, but we report it separately for the direction axis. 
    \item MM - Meet in the Middle, as outlined in \citealt{holte2017mm}. HOG2 implements the MMe variant, which expands on $\max(f, 2g+\varepsilon)$ rather than the $\max(f, 2g)$ of the literature review, with $\varepsilon$ being the same lower bound on edge costs used there. We set $\varepsilon = 1$, as the cheapest move costs $1$ in both movement models. That term tightens the halfway point from $C^*/2$ to $(C^*-\varepsilon)/2$. The difference is small, but it matters for the scores we report, so we return to it in the results.
    \item NBS - Near-optimal Bidirectional Search, as outlined in \citealt{chen2017nbs}. It chooses the next pair to expand so that its expansions stay within a factor of 2 of the necessary number. The near-optimal in the name refers to that count and not to solution quality, as NBS returns optimal paths. 
    \item BAE* - Bidirectional A* with Error, as outlined in \citealt{sadhukhan2013bae}. It expands on the bidirectional estimate $b = f + d$ that the literature review sets out. As implemented in HOG2~\cite{sturtevant2016hog2}, its lower bound is rounded up to the next multiple of the gcd of the edge costs, a device from the bound framework of \citet{alcazar2020unifying}, and that gcd defaults to $1$. The rounding is valid only when every solution cost is a multiple of the gcd, and our costs $\{1, \sqrt{2}, \sqrt{3}\}$ are incommensurable, so no positive gcd exists. At the default the bound inflated to the next integer and the termination test fired before optimality was proven, which returned suboptimal paths silently, with no error and no warning. The correctness checks described below caught it, and they also identified BAE* as the one at fault. HOG2 exposes it as the \texttt{gcd} argument of its \texttt{BAE} constructor, so we set it to $10^{-6}$, after which BAE* matches the optimal cost on every instance. The defect is specific to BAE* among the algorithms we take from HOG2, as the rounding is in its implementation alone. The looser bound costs it extra expansions, so our BAE* expansion counts are not directly comparable to published results on integer cost domains.
    \item BiA* - Bidirectional A*, as outlined in \citealt{pohl1971bidirectional}. As this algorithm was not implemented in HOG2~\cite{sturtevant2016hog2}, we implemented it ourselves. It expands on the priority $f = g+h$. Writing $fmin_F$ and $fmin_B$ for the smallest $f$ value on each open list, it terminates when $U \le \max(fmin_F, fmin_B)$, with $U$ being the best solution cost as the literature review defines it. It strictly alternates between the two directions, and breaks $f$ ties by the larger $g$. A node already closed on the opposite side is skipped rather than expanded, which is the nipping of \citet{kwa1989bs} that the literature review describes. That rule is ours and not Pohl's, and it places BiA* outside the class the floor covers, which is why some of its scores fall below the floor.
    \item GBFS - Greedy Best First Search~\cite{pearl1984heuristics}. We use HOG2's bidirectional variant, which grows a greedy search from each end and joins them, so its reported cost is the sum of the two halves. It is not guaranteed to return an optimal solution. We include it as a fast, suboptimal reference point, and not as a candidate for the must-expand bound.
\end{itemize} A* and reverse A* are unidirectional. MM, NBS, BAE*, BiA* and GBFS all run two searches. Of those five, MM, NBS, BAE* and BiA* are front-to-end and optimal - each direction's heuristic aims at the opposite root rather than at the other frontier~\cite{kaindl1997reconsidered}. The must-expand floor, which we define in the next subsection, is defined for that class.

\subsection{The Must-Expand Floor}
We use the must-expand floor~\cite{eckerle2017sufficient, shaham2017minimal}. \citet{eckerle2017sufficient} give the pairwise condition this rests on, and \citet{chen2017nbs} turn it into a lower bound on expansions - the minimum vertex cover of the graph of pairs that must be separated. The closer an algorithm comes to that bound, the better.

\subsubsection{Notation \& $C^*$}
In the bidirectional domain we conduct two searches, forwards ($F$) from a starting node $s$ and backwards ($B$) from a goal node $t$. We write $d(x,y)$ for the shortest path cost from $x$ to $y$ with the obstacles in place, as against the obstacle free $D$ of the previous subsubsection. We define:
\begin{itemize} \item $g_F(n) = d(s,n)$ = The optimal cost of a path $s \to n$. \item $h_F(n)$ = Heuristic for $n \to t$. \item $f_F(n)$ = $g_F(n)+h_F(n)$ \item $g_B(n) = d(n,t)$ = The optimal cost of a path $n \to t$. \item $h_B(n)$ = Heuristic for $n \to s$. \item $f_B(n)$ = $g_B(n)+h_B(n)$ \item $C^*$ = The optimal solution cost. We compute it from a full A* solve, summing the edge costs along the recovered path, rather than using the value stored in the \texttt{.3dscen} file. That value is the 26-connected optimum, so it does not apply under 6-connectivity at all, and it is rounded to roughly 6 significant figures, which under the \texttt{<} conditions below could misclassify a node sitting exactly on the boundary.\footnote{Because the stored value keeps a fixed number of significant figures, its absolute error grows with the cost. On our largest instances, where costs reach roughly $2{,}400$, the last retained digit sits at $10^{-2}$ and the error runs as high as $5\times10^{-3}$, more than three orders of magnitude coarser than the $10^{-6}$ tolerance our own comparisons use.}
\end{itemize} In 26-connectivity every path cost is a sum of $1$, $\sqrt{2}$ and $\sqrt{3}$, so $C^*$ has no exact floating point representation. We compute it with the same arithmetic and the same summation as the $g$ values it is compared against, so the discrepancy stays at accumulated double precision error. Appendix~A gives the tolerances, how we apply them, and the error budget behind them.

\subsubsection{Must-expand nodes \& the graph}
We restate the pair bound from the literature review, as the derivation below rests on it: $lb(u,v)=\max(f_F(u), f_B(v), g_F(u) + g_B(v))$~\cite{eckerle2017sufficient}. A pair is a must-expand edge if and only if $lb(u,v)$ < $C^*$. As $lb$ uses a maximum, for $lb$ to be less than $C^*$, all three have to be true:
\begin{itemize} 
    \item $f_F(u)$ < $C^*$ - the forward search cannot yet rule out an optimal path through $u$. Equivalently, $u$ lies inside the forward $f<C^*$ contour, meaning the set of nodes whose forward $f$ value is below $C^*$. 
    \item $f_B(v)$ < $C^*$ - the backward search cannot yet rule out an optimal path through $v$. Equivalently, $v$ lies inside the backward $f<C^*$ contour. 
    \item $g_F(u) + g_B(v)$ < $C^*$ - no path that visits $u$ and then $v$ can cost less than $g_F(u)+g_B(v)$, and that bound is still below $C^*$, so we cannot yet rule such a path out.
\end{itemize} If $lb(u,v)\ge C^*$, then no path through $u$ and $v$ costs less than $C^*$. As such, that pair cannot hide a cheaper solution, and an algorithm may return an optimal path without expanding $u$ in the forward search or $v$ in the backward search. Conversely, if $lb(u,v)$ < $C^*$, then the algorithm cannot yet reasonably prove that the optimal path does not go through these two nodes, and as such, at least one of $u$ and $v$ must be expanded~\cite{eckerle2017sufficient}.

Additionally, we also define $G_{MX}$ to be a bipartite must-expand graph, following \citet{chen2017nbs} and \citet{shaham2017minimal}. Its two sides are disjoint copies of the voxel set - a forward copy $L=\{u_F: f_F(u) < C^*\}$ and a backward copy $R=\{v_B: f_B(v) < C^*\}$. A voxel that is both a forward and a backward candidate appears once on each side, as expanding it in the forward search and expanding it in the backward search are two different actions. An edge $(u_F,v_B)$ exists in $G_{MX}$ iff $(u,v)$ is a must-expand pair. The two copies of one voxel are never adjacent, as $d(s,n)+d(n,t)\ge d(s,t)=C^*$ for every $n$ by the triangle inequality. As any algorithm of the class this bound covers must expand at least one endpoint of each edge, the set of nodes it expands is a vertex cover of $G_{MX}$.

The minimum vertex cover (MVC) of $G_{MX}$ is therefore a lower bound on the number of expansions such an algorithm must perform to ensure optimality~\cite{chen2017nbs}.

\subsubsection{Computation}
$G_{MX}$ is bipartite, so its minimum vertex cover is computable in polynomial time by maximum matching. Size is what stops us, as the graph has up to $|L|\times|R|$ edges over contours of $10^5$ to $10^8$ voxels and cannot be built explicitly. What lets us avoid building it is the shape the edges take. Once both endpoints are restricted to the two contours, the only condition left on an edge is $g_F(u)+g_B(v) < C^*$, so the neighbors of $u$ are exactly the backward candidates with $g_B(v) < C^*-g_F(u)$. That ceiling on $g_B$ drops as $g_F(u)$ rises, so a node with a larger $g_F$ has fewer neighbors, and every one of them is also a neighbor of any node with a smaller $g_F$. The neighborhoods therefore form a chain under inclusion, and a bipartite graph with that structure is a chain graph. On a chain graph the cover can be described by a single depth: pick a $\tau$, then take every forward candidate shallower than $\tau$ and every backward candidate shallower than $C^*-\tau$. That is the threshold form~\cite{shaham2018consistent}. We count only over the vertices of $G_{MX}$. We define the two counts as \begin{align*} N_F(\tau) &= \#\{u_F \in L: g_F(u) < \tau\}\\ N_B(\tau) &= \#\{v_B \in R: g_B(v) < \tau\} \end{align*} and the optimal cover is then \[|VC| = \min_\tau \left( N_F(\tau) + N_B(C^*-\tau) \right)\] Membership in $L$ and $R$ already carries the $f<C^*$ conditions, so both counts range over $G_{MX}$ and not over the whole voxel set.

Let $S_\tau = \{u_F \in L: g_F(u) < \tau\} \cup \{v_B \in R: g_B(v) < C^*-\tau\}$. The union is disjoint, so $|S_\tau| = N_F(\tau) + N_B(C^*-\tau)$. Every $S_\tau$ covers every edge, as a node left out of it on both sides would need $g_F(u)\ge\tau$ and $g_B(v)\ge C^*-\tau$, which sum to at least $C^*$ and contradict the edge condition. That alone makes $\min_\tau|S_\tau|$ an upper bound on the MVC. \citet{shaham2017minimal} show that on a chain graph one of the threshold covers is a minimum cover, so the scan returns the MVC itself rather than an upper bound on it. Appendix~C gives both of those steps and the two checks we ran on the scan, one against a direct maximum-matching cover and one auditing the contours the scan is given. To obtain the two $g$-value multisets, we expand each direction's full $f<C^*$ contour, keeping one entry per node so that duplicate $g$ values are counted separately. Note that a consistent heuristic makes a node's $g$ value optimal when it is first expanded, so the forward expansion recovers the true distance from $s$ to every node in its contour, and the backward expansion the true distance from every node in its contour to $t$. We compute $C^*$ first, and then the two contours. As $\tau$ grows, $|S_\tau|$ changes only when $\tau$ crosses one of the values in $\{0\} \cup \{g_F(u)\} \cup \{C^*-g_B(v)\}$, so we sort those breakpoints, evaluate $|S_\tau|$ once between each consecutive pair, and take the smallest.

We compute the floor once per combination of instance, movement model and heuristic weight $w$, the knob the Heuristic Strength Experiment below defines, in a separate binary that runs as its own step before the measured runs. It costs a full A* solve for $C^*$ plus a forward and a backward contour expansion. That is more work than any algorithm we measure. As it is a separate process, the wall-clock and peak memory we report cover the search algorithm alone, and not the floor computation. Every instance in our runs received a computed floor, so no instance is left out of the expansions-against-the-floor comparison for want of one.

\subsubsection{Reporting}
When reporting an algorithm's score, we report it as $\text{\# of expansions} \div \text{MVC}$, which we write as exp/floor throughout. We count expansions per direction, which matches the units of the minimum vertex cover, whose vertices are direction-tagged copies of voxels. With a consistent heuristic no node is re-expanded within a direction, so the numerator and the denominator are in the same units. A score of 1 means the algorithm expanded exactly as many nodes as the bound requires. Scores below 1 are possible for some of our algorithms, and the next paragraphs say which and explain why.

The floor is the least number of expansions needed to prove a path optimal, and GBFS never makes that proof, so dividing its expansions by the floor would measure it against a requirement it does not accept. We therefore report exp/floor only for the six algorithms that guarantee optimality, and for GBFS the raw expansions alongside its solution cost relative to $C^*$.

The bound covers only admissible DXBB algorithms that are front-to-end~\cite{eckerle2017sufficient}, meaning ones that must stay correct under a merely admissible heuristic. An algorithm whose correctness relies on the heuristic being consistent is not in that class and is not bound by the result. Our own BiA* is such an algorithm - it discards a node already closed on the opposite frontier. That is sound only because consistency makes that node's $g$ value final. BAE* is another, as its error term is meaningful only under consistency. \citet{eckerle2017sufficient} name this gap as open work in their conclusions, \citet{alcazar2021consistent} extend the must-expand theory to the consistent case, and \citet{siag2023frontToEnd} enumerate the bounds available once consistency is assumed.

As such we read exp/floor as distance from a floor that binds only the algorithms which must stay correct under a merely admissible heuristic, and we expect the consistency-exploiting ones to fall below it. Unidirectional A* is the exception that anchors the scale. The floor takes no account of the algorithm being measured, so A* is scored against the same $G_{MX}$ as the bidirectional algorithms. It realizes one end of the threshold family: at $\tau = C^*$ every forward candidate enters the cover and no backward one does, as $g_B(v) < 0$ is impossible. With a consistent heuristic A* expands every node with $f<C^*$ and no node twice~\cite{dechter1985generalized}, which is exactly that all-forward vertex cover. Its score therefore cannot fall below 1.

Swapping $s$ and $t$ maps the forward side of $G_{MX}$ onto the backward side, so the MVC is the same in both directions. As such, forward and backward scores are comparable against the same denominator.

Note that exp/floor is undefined when $\text{MVC}=0$. This happens exactly when $h(s)=C^*$ - no node then has $f_F<C^*$, so $G_{MX}$ has no edges. We call an instance non-trivial when $\text{MVC}\ge1$, and we leave the trivial instances out of the expansions' comparison while keeping them for the other axes. The instances this removes are the ones where the heuristic is already exact. They are not simply the short ones. As such, that comparison describes the heuristic-inexact instances. The excluded fraction differs sharply between the two movement models, as Manhattan is exact far more often in 6-connectivity. We report it per group with the results.

\subsection{Implementation and Metrics}
\subsubsection{Implementation}
Our search core is HOG2~\cite{sturtevant2016hog2}, which implements most of the algorithms we evaluated. On top of it we built the voxel environment, implementing both connectivity modes, no-corner-cutting, the weight knob, the floor computation, and BiA*. All of our code is C++17, compiled with g++ at -O2. We ran everything on the BGU HPC cluster, one core per run, and every algorithm on a given instance ran in the same job one after another. The timing comparisons we draw are therefore between algorithms measured on the same node.\footnote{We do not record a CPU model, so our absolute times are not directly comparable with figures published elsewhere.}

\subsubsection{Protocol}
We ran all algorithms against instances of each of the three map families described above, under both movement models. An instance is defined as a (map, start, goal) triple, taken from that map's scenario file. We selected which instances to run as explained in the next section. To measure directional asymmetry we ran A* from each end of every instance. The other five algorithms search from both ends within a single run, GBFS included, as HOG2's variant of it is bidirectional. As such the direction axis covers A* alone, which is the only unidirectional algorithm we run and so the only one for which forward and reverse are distinct.

We cap each run at 60 s of wall-clock time, and at an address space limit of 4000 MB in 6-connectivity and 7000 MB in 26-connectivity. The caps are not there to make the searches terminate, as the graph is finite and every search terminates on its own. They are there to keep us inside our compute budget, since the largest searches otherwise exhaust the available memory and die. We set the memory caps from the observed peak virtual usage in each movement model, with headroom above the largest peak we saw, and picked the time cap to fit the budget rather than deriving it in advance. We therefore report the resulting timeout rates per algorithm rather than arguing that the caps are harmless.

A run that exceeds the time cap is recorded as a timeout, and one that exhausts the address space cap as a failure, which does not imply a peak resident figure anywhere near the cap, as Appendix~B explains. Either way the instance is recorded as unsolved rather than dropped, provided the cluster task it belonged to ran to completion. Where a task itself hit the node's wall-clock limit, the runs it had not yet reached never happened at all, so those instances are missing rather than unsolved. That affected the last instances of two descent levels under 26-connectivity, and we report the gap with the results.\footnote{A different matter from the one descent level we left out of the benchmark altogether.}

\subsubsection{Sampling}
Each map holds 2000 instances. Running all of them is expensive, and offers little advantage over a representative sample.

Instances in the scenario files are graded by difficulty. The grading is not strictly monotonic, but easier cases are generally placed before their harder counterparts - the first 250 sandstone instances have a mean optimal cost of about 305, against about 536 over the full 2000. As such, any prefix of the file is systematically easy. To correct this, we shuffle each map's instance list with a fixed seed and interleave the maps, so that every prefix of the resulting order is itself a representative sample of the family. This prefix property is what our stopping rule needs.

\subsubsection{The stopping rule}
How many instances we run is decided by the data rather than fixed in advance. We run them in the order above in rounds, and after each round we check whether each group's median exp/floor has settled. For each (family, mode, algorithm) we track the median exp/floor and its bootstrap $95\%$ CI (Confidence Interval). What gets resampled is that group's own per-instance exp/floor scores. A resample is a fresh list of the same length drawn from those scores at random with replacement, so a score can appear more than once or not at all. We build 2000 of them under a fixed seed, take the median of each, and read the interval off the 2.5th and 97.5th percentiles of those 2000 medians. It estimates how far the median would move had we happened to run a different set of instances. A group counts as converged when the CI half-width is within $\pm3\%$ of the median, and at least 50 instances contribute to it.\footnote{We need that minimum as exp/floor is concentrated on a few exact values, so a small sample can give a zero-width interval that would otherwise read as convergence.}

Whether to run a further round is decided per (family, mode) rather than per algorithm. If any algorithm in a group has not converged, we extend the whole group and re-run every algorithm over the enlarged range, up to all 2000 instances. As such, every algorithm in a group is measured over the same leading stretch of the shuffled order, which is what makes their medians comparable. Note that the ratio is undefined at $\text{MVC}=0$, so only the non-trivial instances contribute to a CI - the effective sample size is smaller than the number of instances we ran, and substantially so in 6-connectivity. We read the $\pm3\%$ interval as a convergence diagnostic rather than as an inferential interval, and we do not rank two algorithms whose medians separate by less than it.

\subsubsection{The rounds we ran}
The first round ran 500 instances per map in all six groups, and two of them converged there, sandstone and descent under 6-connectivity. The rule called for another round on the remaining four, and we ran it on the two plant groups alone, which took them to 1500 instances per map. Table~\ref{tab:sample} gives the resulting sample, which is the same in both movement models.

We did not extend the two 26-connected groups the rule flagged. At 500 instances per map every algorithm in them except MM was already comfortably inside the target. MM was not, because it times out on almost every instance of both groups, so its interval rests on the handful it solves rather than on the full pool. Table~\ref{tab:sample} gives those counts. On sandstone a further round could not have closed the gap from a sample that small, though on descent it might well have. What settled it was cost, as the same table shows sandstone and descent carrying far more maps than plants, which makes the round we skipped by far the most expensive one available. We report MM's interval as it stands and flag its coverage wherever its numbers appear.

\subsubsection{Verifying optimality}
We verify optimality rather than asserting it, in three independent ways. The first is \texttt{validate}, a separate binary of ours that re-implements the legality test from scratch rather than calling the environment's own move check, so it cross-checks the search instead of agreeing with it by construction. It confirms that the successor generator never produces an illegal step, and that every path any algorithm returns uses legal steps only, with both endpoints free and no corner-cutting. The second compares every returned cost in 26-connectivity against the reference optimum in the \texttt{.3dscen} file, and it is the one oracle we have that sits outside our own code, which agreement among our algorithms cannot supply. The third checks that all optimal algorithms agree on $C^*$ in both modes. All three passed on the runs they cover, and Appendix~D states each check, its tolerance, its coverage, and what it caught.

\subsubsection{Metrics}
We report each algorithm along five complementary axes:
\begin{enumerate} 
    \item[(A)] Search efficiency - node expansions relative to the must-expand floor. This is our primary axis, as it measures how close an algorithm comes to the provable minimum amount of work. 
    \item[(B)] Time - wall-clock runtime and time per expansion. The latter separates search work (how many nodes) from per-node overhead. We read wall-clock as a practical measure, since it also reflects our implementation. BiA* is our own code and the rest come from HOG2, so any wall-clock comparison involving BiA* mixes implementation quality with algorithm. 
    \item[(C)] Memory and robustness - the peak resident memory per run, and the rates of timeout and of memory exhaustion, both over all attempted instances. We keep the two rates apart, as running out of time and running out of memory say different things about an algorithm. Together with peak memory they capture whether an algorithm is practical to run, not just efficient in node count. 
    \item[(D)] Direction - the asymmetry between searching forward (start to goal) and backward (goal to start) on the same instance. Only A* has such an asymmetry to measure, as every other algorithm we run searches from both ends at once.
    \item[(E)] Heuristic strength - how each algorithm's expansions change as the heuristic is weakened, measured by the heuristic strength experiment described below.
\end{enumerate} Throughout this experiment, we focused on the median as opposed to the mean. We did this as the distribution of expansions is heavy-tailed, and several especially hard instances can skew the mean. The timeout and memory-exhaustion rates are kept as guardrails, bounding which instances each median covers. Note that the unsolved instances are the hardest ones, so a median over the solved instances is optimistic, and most optimistic for the algorithms with the lowest coverage. As such, we read the medians together with coverage. Each per-group median is taken over that algorithm's own solved instances, which is why we report coverage beside them, and where we compare algorithms head to head we use a set every one of them solved. Every ratio is formed per instance before we take the median of those ratios, for exp/floor and for the BAE* against A* comparisons alike.

\subsection{Heuristic Strength Experiment}
To locate the point at which bidirectional search overtakes unidirectional A*, we devised a controlled experiment, where we hold all parameters fixed and gradually weaken the heuristic.

\subsubsection{The weight knob}
We define the weight knob $h'(n)=w\cdot h(n)$, where $w \in [0,1]$.
\begin{itemize} \item $w=1$ is the full strength heuristic, Manhattan or voxel depending on the movement model. \item $w=0$ is Dijkstra, where all heuristics are 0.
\end{itemize} Note that $h'$ stays admissible and consistent for all $w \in [0,1]$:
\begin{itemize} \item Admissible: $h(n)\le h^*(n)$, and since $w \le 1$ and $h(n)\ge 0$, we get $h'(n) = w \cdot h(n) \le h(n) \le h^*(n)$. \item Consistent: from $h(n) \le c(n,n') + h(n')$, multiply by $w \ge 0$ and get $w \cdot h(n) \le w \cdot c(n, n') + w \cdot h(n')$. Since $c(n,n') \ge 0$ and $w \le 1$, we have $w \cdot c(n,n') \le c(n,n')$, which gives $h'(n) \le c(n,n') + h'(n')$.
\end{itemize} The same $w$ scales $h_F$ and $h_B$, so both directions stay admissible and consistent. As such, every optimal algorithm stays optimal, and the floor stays well-defined at each $w$. The floor's value depends on $h$, so it moves with $w$. We compare exp/floor only within a fixed $w$, and use raw expansions across $w$.

\subsubsection{Setup}
We set up the experiment so that only one variable moves ($w$), with the domain, the instances and the algorithm set all held constant. That set is A* and the four bidirectional algorithms we measure against it. Reverse A* is left out, as direction is the subject of its own axis and reversing A* tells us nothing about where bidirectional search overtakes it, and GBFS is left out as it is not optimal. We run it under 26-connectivity, on one map from each family - plant01, the Parker sandstone sample, and descent level20 - over 80 instances per map taken from the same seeded shuffle as the main sweep, sweeping $w$ over $\{1.0, 0.8, 0.6, 0.5, 0.4\}$. The sweep is denser at the lower end, where the crossover falls. Weakening the heuristic grows the searches quickly, so this experiment uses a 300 s cap per run rather than the 60 s of the main protocol. That cap is why we run it separately rather than folding it into the sweep, as raising the cap there would have changed the main sweep's own timeout rates, and $w$ is a parameter the sweep deliberately holds fixed. For each $(w, \text{algorithm})$ we record the median raw node expansions, together with the fraction of instances solved at that weight. We use raw expansions rather than exp/floor, as the floor itself shifts when the heuristic changes.

This experiment varies the scale of the heuristic, and not the structure of its inaccuracy, so it does not test claims about where a heuristic is inaccurate. It covers one map per family and not the full sweep, as repeating the sweep at five weights under a fivefold longer cap was beyond our compute budget, so we read it as evidence that the behavior holds across the three structures rather than as a measurement of its size. As coverage falls with $w$ for the slower algorithms, we report each median alongside its coverage, and we do not compare medians across algorithms whose coverage differs by much. The section that follows reports axes A to D from the main sweep and axis E from this experiment.

\section{Experimental Results}
The stopping rule took us to 1500 instances per plant map and 500 per sandstone and descent map, drawn in the shuffled order described above. Every median below is taken over solved instances, and the full per-instance data is released with the code.

\subsection{Convergence and exclusions}
We report each median with a bootstrap $95\%$ CI, and we ran each group until that interval was within $\pm3\%$ of its median, or until a further round could not have closed the gap, for the reasons the previous section gives. Thirty of the thirty-six algorithm and group pairs converged inside the target. Two groups converged completely, descent and sandstone under 6-connectivity, where every algorithm reached under $2\%$.

The six pairs that fell short we report with their wider intervals rather than dropping them. MM failed to converge in every diagonal mode. The sample sizes are the ones the stopping rule reached, as the previous section describes, and MM is short of the target in every 26-connected group.

\subsubsection{Why some scores fall below the floor}
For two of the four the reason is the one the Methodology gives, that an algorithm whose correctness rests on consistency sits outside the class the bound covers. BAE* is that case through its error term and our BiA* through the rule we added, and \citet{eckerle2017sufficient} name BS*~\cite{kwa1989bs} as the same case and leave it as future work. Neither is a violation, and neither is the interesting one.

NBS and MM are not candidates for that explanation as published. \citet{eckerle2017sufficient} present NBS as an admissible DXBB algorithm and describe MM as admissible, so the bound applies to both. The implementations we run are not quite those two algorithms, and that difference accounts for most of what follows.

\subsubsection{MM and the $\varepsilon$-refined graph}
MM sits just below the floor, and the gap is a difference of definition rather than a saving. HOG2 implements MMe, the variant of \citet{holte2017mm} that expands on $\max(f, 2g+\varepsilon)$ where $\varepsilon$ is a lower bound on the edge costs, fixed at $1$ in our build. MMe expands the candidates with $g < (C^*-\varepsilon)/2$, while our floor is the threshold cover at $\tau=C^*/2$, computed from the must-expand condition without the $\varepsilon$ refinement that \citet{shaham2018consistent} provide. The shortfall is therefore the band of nodes whose $g$ falls between $(C^*-1)/2$ and $C^*/2$, and it is deterministic rather than incidental. Its $73$ cases bear this out, as the worst is $0.976$ and the median is $0.998$. On that worst case, a diagonal plant instance, the band holds $228$ forward and $224$ backward candidates against an observed shortfall of $447$ nodes, or $2.4\%$. The dips are wider on the diagonal maps, at $0.976$ against $0.9949$ on the integer-cost maps, and that follows from the same mechanism. Under 6-connectivity every $g$ is an integer, so a band of width one half is almost empty, while the incommensurable costs of 26-connectivity fill it. These cases are a loose denominator and not an excursion below the bound.

\subsubsection{NBS, and two populations}
NBS splits into two groups with two different causes, and the $\varepsilon$ shell sets the boundary between them. Its $297$ cases reach $0.377$ with a median of $0.913$, and $290$ of them sit on descent maps, with $4$ on plants and $3$ on sandstone.

A minority of them have the same cause as MM's. NBS also commits to the $\varepsilon$-refined must-expand graph, as its queue adds $\varepsilon=1$ to the pair bound before comparing it against the incumbent, while our floor applies no such refinement. On a diagonal plant instance scoring $0.980$ the refined cover holds $12{,}553$ vertices against $12{,}845$ for the unrefined one, and NBS expands $12{,}588$. It therefore covers in full the graph it actually commits to, and its shortfall against our floor is the $\varepsilon$ shell of $292$ vertices, or $2.3\%$. The shell is what caps this explanation. Across our instances it never exceeds $2.4\%$, so it can only account for cases within that distance of the floor, and there are $105$ of those with a median of $0.9969$. They are a loose denominator rather than a saving.

The other $192$ fall further than the shell can reach. Their median is $0.826$, and they run down to $0.377$, so no refinement of a few percent explains them.

\subsubsection{Separating the two rules}
Two candidates for them sit in the implementation rather than in the published algorithm, and a rebuild separates the two. The first is a rule that discards a generated node already closed on the opposite frontier, which HOG2 compiles unless \texttt{ADMISSIBLE} is defined and which our build leaves undefined. That is the same consistency-exploiting rule we added to our own BiA*, and it places NBS outside the class for the same reason. The rule is not new, and naming it locates all of this in the literature. It is the nipping of \citet{kwa1989bs}, and BS* is the algorithm \citet{eckerle2017sufficient} name when they set aside algorithms that rely on consistency. \citet{holte2017mm} make the same point from the other side, observing that an algorithm which meets in the middle needs neither consistent heuristics nor special mechanisms such as Kwa's nipping and pruning. So the theory anticipated this case, and what we add is that a current implementation of an in-class algorithm quietly contains it. The second is its termination, which can fire once its lower bound reaches the incumbent and need not wait until the must-expand pairs are covered. Defining the flag disables the first and leaves the second, so a comparison of the two builds isolates the discard.

We ran that comparison on twenty-four instances, drawn from four map and movement-model groups so that neither the geometry nor the cost model is held fixed. Twelve are the deepest cases, diagonal instances of one descent level over covers of $4.5$ to $9.3$ million vertices, where the default build scores $0.377$ to $0.493$. The other twelve cover a 6-connected descent level that alone holds $127$ of the $192$, a second diagonal level, and a second 6-connected one, where the default build scores $0.574$ to $0.834$. On all twenty-four the admissible build lands above the floor, between $1.11$ and $1.47$, and both builds return the same optimal cost on every instance. Figure~\ref{fig:nipping} shows every pair. There are no exceptions. The discard is therefore the mechanism, and it is an efficiency that consistency permits rather than a correctness fault, which is why it never shows up as a wrong answer.

The flag that controls this is undocumented, and the one comment in the framework that names it states it is defined in a header where it is in fact commented out, so a reader who trusted that line would take the in-class build to be the default. We report it because the rule is sound, and the silence is the problem: anyone measuring this implementation against the must-expand bound would compare the two without knowing they differ. Appendix~E gives the second, rebuild-free argument that these cases are not a denominator artifact, the discard counts behind them, and the full state of the flag in the source.

\subsubsection{NBS against its own factor of two}
One number in Table~\ref{tab:expfloor} looks like a violation and is not. NBS's median on plants under 6-connectivity is $3.41$, above the factor of two it guarantees, and it clears twice the cover on $84\%$ of that group rather than on a tail. The guarantee is narrower than the ratio we report. \citet{chen2017nbs} build the must-expand graph from pairs with $lb(U,V)<C^*$ strictly, and their Theorem 3 bounds only the expansions NBS makes in covering those pairs. Expansions at $f=C^*$ fall outside that accounting, and they note that NBS may make many of them where another algorithm does not. Our exp/floor puts that whole plateau in the numerator and none of it in the denominator. The cover is not undersized here, as A* sits at $1.06$ on the same instances, and NBS expands $2.42$ times what A* does per instance at the median. Note that $83.4\%$ of this family's 6-connected instances have $\text{MVC}=0$ and are excluded from this axis, so that share is evidence about the family and not about this median. Manhattan is exact end to end on most of these instances, and on the ones that remain it is still exact over the open floor, so the $f=C^*$ plateau is large. \citet{chen2017nbs} report the same mechanism on the pancake puzzle under the GAP heuristic, where the heuristic is often perfect and expansions concentrate at $f=C^*$.

One caution on coverage goes beyond the table markers. Every bidirectional algorithm has a non-trivial diagonal timeout rate, so all of their medians are over solved instances and are mildly optimistic, BAE* included.

\subsection{(B) Time}
A* is the fastest algorithm in every diagonal configuration, and the bidirectional algorithms cost it roughly $1.6$ to $3.3$ times in wall-clock time there. It is not fastest everywhere. On plants under 6-connectivity BiA* runs at a median of $1.6$ ms against A*'s $1.9$ ms, over the full sample that both solve, and it also expands fewer nodes at the median. MM's $1.8$ s median on sandstone under 26-connectivity is below A*'s $3.3$ s, but that is survivorship rather than speed, as MM solves $116$ of $5{,}500$ there against A*'s full sample. Per expansion the gap is much smaller - A* runs at $1.9$ to $2.7\,\mu$s on diagonal maps, against $2.8$ to $3.9\,\mu$s for BiA* and NBS and $3.7$ to $4.6\,\mu$s for BAE*. As such, most of the wall-clock difference comes from expanding more nodes and not from a dearer node.

MM is the exception, and it pays on both counts. Its per-expansion cost on diagonal maps runs from $8.4$ to $19.6\,\mu$s, four to seven times A*'s, and it also expands more nodes. Note that MM's per-expansion median pooled over all groups looks low at $1.4\,\mu$s. That is survivorship - the figure is dominated by the 6-connected groups, where it solves everything and the searches are small.

That constant is not a property of the algorithm, and locating it changes how the robustness result below should be read. HOG2's MM keeps its open nodes in a histogram bucketed by $(g,h)$ and recomputes the termination bound by iterating that histogram on every expansion, which costs the number of distinct buckets rather than the logarithmic cost of a heap. The implementation carries its own note that this should be made more efficient. The cost of the scan is set by how many distinct $g$ values the open list holds, and that is where the cost model enters. On a diagonal plant instance a forward contour of $19{,}379$ nodes holds $14{,}497$ distinct $g$ values, as sums of $1$, $\sqrt{2}$ and $\sqrt{3}$ rarely coincide. Under 6-connectivity the same contour holds a few hundred, as every $g$ is an integer bounded by $C^*$. This is still a theory-against-practice result, and it is a sharper one than a budget artifact, as it says where the gap between the two actually sits. MM is designed to bound its expansions and it does. What defeats it here is the cost of proving it may stop.

\subsection{(D) Direction}
Reverse A* expands between $1.35$ and $3.04$ times the bound where forward A* sits at $1.00$ to $1.06$. Note that this is largely a property of the benchmark and not a discovery about the domain. \citet{nobes2023voxel} rank each instance by the cheaper of its two search directions, measured in A* expansions, and then output it in that orientation, so forward search is the easier direction by construction on all three families. Their Figure 5 states that the three families we use were designed to control for the direction of bias. We therefore measure the size of that built-in orientation under our heuristic and cost model, and not whether it exists.

Figure~\ref{fig:asym} compares the two directions directly, as the median of the per-instance ratio rather than a ratio of the two medians. Read that way the effect is smaller than Table~\ref{tab:expfloor} suggests, at $1.35$ to $1.72$ times, and plants under 6-connectivity sits at exactly $1.000$. That figure is a straddle and not a plateau. On that group $32.9\%$ of instances have reverse expanding fewer nodes than forward, $17.9\%$ land exactly on parity, and $49.1\%$ sit above it, so the cumulative distribution crosses one half inside the spike at $1.0$. An exact heuristic is not the explanation, as $83.4\%$ of this group has $\text{MVC}=0$ while only $17.9\%$ expands equally in both directions. What the median conceals is the tail, which is severe. The same ratio reaches $12$ at the 75th percentile, $102$ at the 90th and over $3000$ at the 99th, and that tail is what separates the two floor-relative medians of Table~\ref{tab:expfloor} by a factor of three. We report both, as the per-instance median says what a typical instance costs while the floor-relative figure says how heavy the tail is.

One part of the result is not explained by the construction. The benchmark ranks instances by A* expansions under its voxel heuristic, which is the 26-connected distance with no corner cutting~\cite{nobes2023voxel}, so our 6-connected runs inherit an orientation chosen under a different move model. The widest gap we measure, $3.04$ on plants under 6-connectivity, is in exactly that case, and it is also one of the medians that did not reach the $\pm3\%$ interval. We read it as indicative.

\subsection{(E) Heuristic strength}
Theory points to heuristic strength as the primary driver of when bidirectional search stops losing to A*~\cite{alcazar2020unifying, siag2025bridging}. To locate that reversal, we swept the weight knob over $w \in \{1.0, 0.8, 0.6, 0.5, 0.4\}$, under the setup given in the Methodology.

Figure~\ref{fig:xover} plots the same three series. The direction of the effect is the same on all three maps. As the heuristic weakens the ratio falls monotonically - from $1.04$ to $0.61$ on plant01, $0.99$ to $0.54$ on Parker, and $1.47$ to $1.04$ on level20. On plant01 it crosses $1.0$, so BAE* goes from expanding slightly more than A* to expanding substantially fewer. Parker starts at parity and pulls clear. On level20 it never crosses, though it ends close to it. This is the behavior the theory predicts, and it is the robust part of this experiment.

We do not draw a family-level conclusion from it. The main sweep gives us the same ratio at full strength on every map, and it varies as much within a family as between them - across the five plant maps it runs from $1.03$ to $2.28$, and across the descent levels from $0.90$ to $2.12$. Note that those figures come from the main sweep, so plant01 reads $1.14$ there against $1.04$ in Table~\ref{tab:xover} - the two runs use different samples and different caps, and we do not treat the difference as a result. The three maps we swept are not representative of their families in this respect, so we report the trend per map and make no claim about which geometry favors which method.

MM collapses on all three maps. Below full strength it solves $0$ to $3$ of $80$ instances, and $0$ of $80$ on level20. It does not overtake anything under a weakened heuristic - it stops being usable. Note that this does not test the MM0 comparison from the literature review, as weakening the heuristic is not the same as removing it, and we did not run MM0. An earlier run on six instances appeared to show MM overtaking A* - that result rested on a single solved instance, and we retract it.

BiA* and NBS never overtake A* at any weight. As such, the advantage this experiment shows belongs to the error-exploiting method rather than to meet-in-the-middle. Note that we compare raw expansions here rather than exp/floor, as the bound moves with $w$.

\subsection{GBFS as a speed and quality reference}
GBFS is not cost-optimal, so the bound does not apply to it, and we report it separately. Pooled over the sweep its median solution cost is $1.337$ times $C^*$ and its median expansion count is $27{,}655$. The quality penalty varies widely by group, from $1.03$ times $C^*$ on plants under 26-connectivity to $2.14$ on sandstone under 6-connectivity, so the pooled figure understates how poor its paths become on the harder groups. It is the fastest way we have to get a path and the worst path we report. That is the trade it exists to illustrate.

\subsection{Cost agreement}
The optimal algorithms agree on cost everywhere. Across every group, A*, reverse A*, MM, BiA*, BAE* and NBS return identical costs on every instance all of them solved, with no wrong-cost result anywhere in the sweep. Note that for MM on diagonal maps this covers only the small fraction it solves.

The legality audit found no illegal move, over an earlier subset rather than the representative sample. Appendix~D gives its counts and says what that coverage does and does not license.

\section{Conclusions and Summary}
We set out to measure how close bidirectional search comes to a provable floor on 3D voxel maps, and to find where its theoretical efficiency translates into practical performance. On this domain the two come apart more than the theory alone suggests, and the clearest cases are negative.

Against the must-expand floor, A* is the algorithm to beat, and it is hard to beat. Its median sits within $6\%$ of the bound in every configuration, and BiA* and NBS hold a band of $1.5$ to $1.7$ times it on the diagonal maps. That band is a good result rather than a poor one, as no algorithm of this class has a worst case better than twice the bound, and the bound is reached only by an algorithm given a parameter it cannot know in advance. Note that the floor tracks A*'s own contour on most instances, within $1.5\%$ at the median on every diagonal group, and departs from it only where the bound claims real room. That minority is where the comparison does independent work, and there BiA* comes in at $3.53$ against A*'s $6.13$.

Two results say where the theory stops translating. BAE* is the only algorithm that overtakes A*, and it does so as the heuristic weakens, ending below it on two of the three maps we swept. We do not read that as a family-level result, as the ratio varies as much within a family as between them. MM is the sharper case. It is designed to bound its expansions, and it does, yet on the diagonal maps it cannot finish the instance at all, timing out on $77$ to $98$ percent of them, and five times the budget does not help. The cause is not how many nodes it expands but what each expansion costs, and that cost is an implementation choice meeting our cost model badly.

NBS falls below the floor on $297$ instances, and they divide into two causes. A shell of at most $2.4\%$, from a refinement NBS applies to the must-expand graph and our floor does not, accounts for the $105$ cases within that distance. The other $192$ we traced to a rule in HOG2's NBS that discards a node already closed on the opposite frontier, which is the rule that also places our own BiA* outside the bound's class. Disabling it lifts NBS above the floor on all twenty-four instances we tested, with the optimal cost unchanged. That experiment also checks our floor where we most needed one, as an algorithm inside the class must expand at least a cover, and unlike A* NBS is not held above the floor by construction.

The results come with real limits. Every median is taken over solved instances, so all are optimistic, and most so for MM, which solves the fewest. On plants under 6-connectivity the heuristic is exact on $83.4\%$ of instances, so the floor axis there speaks for only $1{,}247$ of $7{,}500$. The heuristic-strength experiment covers one map per family rather than the full sweep, and the legality audit ran on an earlier subset than the reported sample. We report each limit next to the number it qualifies rather than in a separate caveat.

\subsection{Contributions}
We claim four contributions, and the body supports each in the place named.
\begin{itemize} \item \textbf{A per-instance floor for this domain.} The must-expand bound had not been computed per instance on 3D voxel maps, and at contour sizes of $10^5$ to $10^8$ it cannot be computed by building the graph. We compute it in threshold form for every instance we report, and we validate the scan against a direct minimum cover. \item \textbf{The gap between a published algorithm and its implementation is where this domain does its damage.} In three of the four algorithms we took from one framework the implementation and the algorithm come apart in ways that change what the bound says about them. One returns suboptimal paths silently on incommensurable costs, one carries a rule that leaves the class the bound covers, and one pays a per-expansion cost that grows with the number of distinct path costs. None of the three is announced to anyone using the library, and none is visible as a wrong answer. \item \textbf{An account of every score below the floor.} Sub-floor scores divide into a loose denominator and a genuine class escape, and the two are separable. The $\varepsilon$ shell accounts for $105$ of NBS's $297$ cases, and a single compile flag accounts for the rest, lifting all twenty-four instances we tested from below the floor to above it with the optimal cost unchanged. \item \textbf{A caution about the benchmark.} Its scenario files are difficulty-graded, so sampling them by prefix is systematically easy and moved our own headline figure by roughly three times. It also writes each instance in its cheaper search direction, so a forward advantage is built into the data rather than found in it.
\end{itemize}

\subsection{Future work}
Four things follow directly from what we could not settle here.
\begin{itemize} \item \textbf{Re-run MM against an incremental termination bound.} Its collapse here is the cost of proving it may stop, not the expansions it makes, so an implementation that maintains the bound incrementally would separate the algorithm from this implementation of it. That is the one measurement that would tell us whether meeting in the middle is viable on this domain at all. \item \textbf{Run the admissible NBS build across the full sweep.} We ran it on twenty-four instances to identify a mechanism. Run everywhere it would give the first measurement of how far an in-class NBS actually sits from the floor on this domain, which is the number the theory is about. \item \textbf{Widen the heuristic-strength sweep.} It covers one map per family, and the ratio varies as much within a family as between them, so the crossover we report is per map. Several maps per family would settle whether the crossover is a property of the geometry. \item \textbf{Measure generations, and run MM0.} Our driver records generated nodes and our aggregation drops them, so an axis for generated nodes costs a re-aggregation rather than a re-run. MM0 is the comparison \citet{holte2017mm} predict will favor the brute-force variant under a weak heuristic, and weakening a heuristic is not the same as removing it, so our sweep does not test it.
\end{itemize}

\section{Appendix A: Numerical tolerances}
All strict comparisons against $C^*$ use an absolute tolerance of $10^{-6}$, and the threshold scan uses $10^{-7}$. We apply both conservatively - a node or a pair within the tolerance of the boundary is dropped and never added - so the floor stays a valid lower bound. \section{Appendix B: Run accounting}
The cap binds a small tail. We sampled $27{,}500$ instances per movement model - $1500$ on each of the five plant maps and $500$ on each of the eleven sandstone and twenty-nine descent maps - and ran seven algorithms on each, so $385{,}000$ runs were planned. Of those, $742$ never ran, as the $106$ descent instances noted above did not finish inside the cluster's allocation, and a further $35$ runs on those same two levels are missing from the log. That leaves $384{,}223$ records. Our raw log also contained four rows where a run that finished was additionally recorded as a timeout, from a race in the run harness that we have since fixed, and the data we report excludes them. Those rows never entered any median, as we compute expansions, ratios, time and memory over solved runs only, and dropping them moves one reported figure by $0.01$ percentage points. Of the records, $302{,}358$ are solved, $27{,}015$ timed out and $54{,}850$ are GBFS runs, which we record as suboptimal rather than solved as GBFS is not cost-optimal. GBFS accounts for $36$ of the timeouts as well, so every suboptimal record is a GBFS run while not every GBFS run is suboptimal. Across the solved runs the median wall time is $3.0$ s, the 99th percentile is $38.4$ s and the 99.9th is $54.3$ s, so the 60 s cap sits at roughly $1.6$ times the 99th percentile and $235$ solved runs finish within 5 s of it. We therefore report timeout rates per algorithm rather than treating the cap as harmless. The two memory figures we quote are also not the same quantity. The cap is on address space, the total a process has mapped, while the memory axis reports peak resident memory, the part actually held in RAM. A search can map a large arena and touch little of it, so it can exhaust its address space while its resident peak is still well below the cap, and a memory failure therefore does not imply a peak close to the cap.

\section{Appendix C: The threshold cover}
Recall $S_\tau$ from the Computation subsection. We show here that $S_\tau$ is a valid vertex cover for every $\tau$, so that $\min_\tau|S_\tau|$ is an upper bound on the MVC. That this bound is tight - that some threshold cover attains the minimum - we take from \citealt{shaham2018consistent}, and do not reprove:
\begin{itemize} \item Valid cover - for any edge $(u,v)$ we have $g_F(u)+g_B(v)<C^*$. If neither endpoint were in $S_\tau$, then $g_F(u)\ge\tau$ and $g_B(v)\ge C^*-\tau$, summing to $\ge C^*$, a contradiction. So $S_\tau$ covers every edge, for any $\tau$. \item Tightness - once we restrict to the two $f<C^*$ contours, the only edge condition left is $g_F(u)+g_B(v)<C^*$, so the forward neighborhoods are ordered by inclusion. \citet{shaham2018consistent} and \citet{shaham2017minimal} before them show that some threshold cover attains the MVC once the neighborhoods are ordered this way, which gives $\min_\tau|S_\tau| = \text{MVC}$. The result is \citet{shaham2017minimal}'s, and \citet{shaham2018consistent} restate it in a form valid for any non-negative $\varepsilon$, including the $\varepsilon=0$ case we use. This is the direction our reported floor rests on, and we take it as given without reproving it. Note that consistency is why the $g$ values in the edge condition are the instance's optimal distances. We also checked the scan itself against a direct minimum vertex cover computed by maximum matching, over $3000$ random chain graphs, and the two agreed on every one. As the restricted graph is a chain graph, this confirms the scan returns the exact minimum cover and not merely an upper bound on it. We also audited the floor directly on the instance where the closest algorithm to it came in furthest below, a diagonal plant instance on which MM scored $0.976$. The forward and backward candidate sets there match what A* and reverse A* expand to within four nodes out of roughly twenty thousand, so the contours are not over-collected, and $C^*$ agrees between the floor binary and the measured run. The scan's value is the minimum over every breakpoint and not a local one. The floor on that instance is the exact minimum cover.
\end{itemize}

The floor is checked in two ways, and the second covers what the first does not. The threshold scan is checked against a direct maximum-matching cover on $3000$ random chain graphs, which establishes that the scan returns the true minimum of the graph it is given. The construction of that graph, meaning the two candidate contours and $C^*$, is audited directly on a plant instance. On the descent instances where the sub-floor scores run deepest we have an empirical check instead. The admissible NBS build expands more than the floor on every one of them, and as an algorithm inside the class must expand at least a cover, that is an achieved count consistent with the floor. Note that A* cannot serve the same purpose, as its score is bounded below by $1$ by construction, while NBS carries no such guarantee.

\section{Appendix D: Correctness checks}
To make our results trustworthy, we must not only assert optimality - we must also verify it. This was done in three ways:
\begin{enumerate} \item An independent auditor re-implements the move rule from scratch, sharing no code with the environment's own move test, and verifies that both the successor generator and every returned path only contain legal non-corner-cutting moves - adjacency, both endpoints free, and every voxel a diagonal move clips free. The auditor is itself checked by a negative control, \texttt{validate --self-test}, which runs seven hand-built cases whose expected answers do not depend on the auditor's own logic: corner and edge moves that clip a blocked voxel, a corner move whose whole $2\times2\times2$ box is free, a non-adjacent pair, a diagonal offered under 6-connectivity, and a blocked source and a blocked target. All seven pass. Without that control the zero-illegal result would carry no weight, as a checker that always returned legal would report the same zero while failing six of the seven cases. \item In 26-connectivity we verify every returned cost against the reference optimal cost in the \texttt{.3dscen} file, to within $10^{-2}$. Note that we rejected that same value for computing $C^*$ because it is too coarse for the strict comparisons the bound needs. It is still useful here, as this check looks for gross error rather than boundary classification, and a wrong cost would miss by far more than $10^{-2}$. This is an oracle external to our implementation, which agreement between our own algorithms cannot give us. It is not available in 6-connectivity, as the reference costs are computed with diagonals and do not apply there. \item In both modes we verify that all optimal algorithms agree on the $C^*$ value, to within $10^{-2}$. In 6-connectivity this is the only optimality check we have. Note that this check is what localized the BAE* defect described above, as BAE* was the only optimal algorithm returning a cost the others did not. We leave GBFS out of it throughout, as it is not guaranteed to return an optimal solution.
\end{enumerate} All three checks passed on the runs they cover. Note that the legality audit covers an earlier subset rather than the representative sample, and we report the counts and the coverage of each check with the results.

\section{Appendix E: The discard rule in detail}
A second argument reaches the same conclusion without the rebuild. The $\varepsilon$ shell can be measured directly, and on the 6-connected instances above it never exceeds $0.25\%$ of the cover, as integer costs leave the half-unit band nearly empty, while on three of them it is exactly zero. Those same instances sit $17$ to $43\%$ below the floor. A shell two orders of magnitude too small cannot account for that shortfall, so these cases are not a denominator artifact even before the flag is set.

The counts show why so small a rule moves so much. Across the twenty-four the discard fires between $732$ and $148{,}064$ times, while the expansions it saves run from $1.2$ to $8.5$ million, two to three orders of magnitude more. Each discarded node sits at the root of a subtree that is then never generated, so how high in the search it sits sets the amplification, and that varies from $40$ to $2455$ times rather than holding at any one figure. The 6-connected instances make the point most sharply, as they nip the fewest nodes and gain the most from each - on one of them $732$ discards account for $1.8$ million expansions.

The flag that controls all of this is undocumented, and the one comment that names it is wrong. It appears twice as a commented-out define, each time with no note of what it does or that leaving it off costs admissibility, and no README or paper in the framework mentions it. The single line of prose that refers to it says the flag is defined in the header where it is in fact commented out. A reader who trusted that line would take the in-class build to be the default, when the shipped default is the opposite.
